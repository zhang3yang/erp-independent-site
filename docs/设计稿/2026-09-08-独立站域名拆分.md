# 独立站：把前台和买家中心拆成两个域名

2026-09-08 定的方案。改的是康辰站（`kangchen.vclinker.com`），统领站以后照做。

## 一句话

现在整个站都在 `buyer.kangchen.vclinker.com` 上。改成：
逛街的人在主域 `kangchen.vclinker.com`，「我的东西」在 `buyer.kangchen.vclinker.com`。

两个域都能认出你是谁，用的是**同一个会话**，只是各拿一份 Cookie。

## 为什么

用户要求登录的人和没登录的人不在同一个域名上。

主域 `kangchen.vclinker.com` 本来就解析到 49.234.194.194，只是 nginx 上没配、
没证书，所以打不开。域名和备案都是现成的（2026-09-08 确认）。

## 谁在哪个域名上

**主域 `kangchen.vclinker.com`** —— 商城

| 路径 | 是什么 |
|---|---|
| `/` | 首页 |
| `/products`、`/products/[code]` | 商品列表、商品详情 |
| `/cart`、`/checkout` | 购物车、下单 |
| `/login`、`/register` | 登录、注册 |
| `/forgot-password`、`/reset-password`、`/verify-email` | 找回密码、验证邮箱 |
| `/robots.txt`、`/sitemap.xml` | 给搜索引擎看的 |

**`buyer.kangchen.vclinker.com`** —— 我的东西

| 路径 | 是什么 |
|---|---|
| `/account` | 账号资料、地址簿管理 |
| `/orders`、`/orders/[id]` | 我的订单 |

这几页不给收录。

两边的路径前面都可以带语言前缀，比如 `/ja/products`、`/ja/orders`。

**规则是白名单：上面那张 buyer. 表是写死的清单，清单以外的路径一律归主域。**
所以像 `/3d-demo` 这种没列出来的页面，自动归主域。

### 登录页放在主域，不放在 buyer.

**2026-09-08 用户明确确认过这一条**（「登入也放主域」）。它和「登录的人去 buyer.」
这个说法有出入，所以专门问过一次 —— 以后别再当成疏漏改回去。理由：

1. **登录入口在每一个公开页的右上角。** 点一下就跳到另一个域名去输密码，
   等于在教用户「在别的域名上输本站密码是正常的」。钓鱼就是这么得手的。
2. **登录完人通常是继续逛。** 在主域登录，登完就在该在的地方，不用再跳回来。
3. 结算页要用地址簿，主域本来就得认人（见下一节），登录放主域最顺。

买家中心（我的订单、账号资料、地址簿管理）还是在 buyer. 上，
「登录的人的地盘和逛街的人的地盘分开」这件事没有变。

## 核心：两个域共用一个会话

### 会话现在长什么样

```
Cookie: BUYER_SESSION=<32 字节随机串>    HttpOnly, SameSite=Lax, Secure, host-only
                   |
                   v
Redis:  station:buyer:session:<串>  ->  <买家编码>     TTL 30 天，滑动
```

关键点：**Cookie 里装的是一把钥匙，不是身份本身。** 真正的会话在 Redis 里。
这是 `BuyerSession` 现有的设计，不是这次改的。

### 做法：两个域的 Cookie 装同一把钥匙

```
主域      BUYER_SESSION=abc123   host-only，只发给主域
                                    \
                                     +--> Redis: station:buyer:session:abc123 -> BUY0001
                                    /
buyer.    BUYER_SESSION=abc123   host-only，只发给 buyer.
```

两份 Cookie，各自 host-only，**内容相同**，指向同一个 Redis 键。

### 这样做省掉了什么

**退出登录不用写任何同步代码。** 在任意一边点退出，`BuyerSession.end()`
删掉那个 Redis 键，另一个域的 Cookie 立刻变成一把开不了门的废钥匙 ——
下一个请求查不到，就是未登录。

这是不透明令牌（而不是 JWT 那种签名令牌）白送的好处：**删掉键就等于立刻踢下线。**
如果当初用的是签名令牌，退出就真得两边同步，而且签出去的令牌在过期前撤不回。

**也不用放宽 Cookie 的 Domain。** 两份 Cookie 都是 host-only，
谁也不会跟着图片请求发到腾讯云 COS（`file.` 子域是 CNAME 到那边的，
指向 `kangchen-1479674498.cos.ap-shanghai.myqcloud.com`，不经我们的机器）。
如果改成 `Domain=.kangchen.vclinker.com`，会话令牌会落进腾讯云的访问日志，
HttpOnly 挡不住 —— 它挡的是 JS 读取，不是发送。

### 为什么主域也必须能认人

因为**地址簿**。工作区里正在做的这个功能（`SiteBuyerAddress*`、
`checkout/index.vue` 的「选择已保存的地址」下拉框）要求结算页能读到买家的地址。
`BuyerAccountController` 里那四个地址接口每一个都要会话：

```java
@GetMapping("/addresses")                 -> requireBuyer(request)
@PostMapping("/addresses")                -> requireBuyer(request)
@PostMapping("/addresses/{id}/default")   -> requireBuyer(request)
@PostMapping("/addresses/{id}/delete")    -> requireBuyer(request)
```

而结算页必须在主域 —— **下单不能挡登录**，匿名买家也要能买。
所以主域必须能认人。这一条是硬的，绕不过去。

## 钥匙怎么从主域传到 buyer.

不能直接把 `abc123` 拼在 URL 上。URL 会进浏览器历史、进 Referer 头、
进 nginx 访问日志 —— 那等于把钥匙抄在好几个地方。

用一张**一次性票**换：

```
1. 买家在主域登录成功
   -> 主域种 BUYER_SESSION=abc123
   -> 后端顺手写一张票：Redis  station:buyer:handoff:<票> -> abc123   TTL 60 秒

2. 前端把浏览器导到：
   https://buyer.kangchen.vclinker.com/openapi/site/account/handoff?t=<票>&to=/orders

3. buyer. 上的 handoff 接口：
   -> 拿票去 Redis 换 abc123（读完立刻删，一张票只能用一次）
   -> 种自己的 BUYER_SESSION=abc123（host-only，只发给 buyer.）
   -> 302 到 /orders

4. 从此两个域都有钥匙了，不用再交接。
```

**只在登录成功后交接这一次。** 之后 30 天里两个域之间怎么来回走都不用再交接。

### 新增两个接口

| 接口 | 要会话吗 | 干什么 |
|---|---|---|
| `POST /openapi/site/account/handoff-ticket` | 要 | 发一张票，返回票号 |
| `GET /openapi/site/account/handoff?t=&to=` | 不要 | 它就是来拿会话的 |

放在 `/openapi/site/account/` 下面，nginx 不用为它加规则。

不要挂在 `/sso` 上。那个路径已经被管理台的 `SsoController` 占了
（ERP「进入管理」跳转用的），而且它只在 `console.` 域上转发。两回事，别混。

### ⚠ handoff 不能调 `BuyerSession.start()`

`start()` 干的第一件事是 `end(request, response)` —— 那是防会话固定用的，
它会**删掉旧令牌的 Redis 键**，然后生成一个**新**令牌。

handoff 要的正好相反：拿一个**已经存在**的令牌，只种 Cookie，不碰 Redis。
调 `start()` 的话，buyer. 会拿到一个跟主域不同的新令牌，两边就不是同一把钥匙了，
「删一个键两边一起失效」这个前提当场作废，而且表面上完全看不出来 —— 两个域都能用，
只是退出的时候另一边不掉线。

所以要给 `BuyerSession` 加一个新方法，比如 `adopt(response, token)`：只种 Cookie。

这样做不会引入会话固定漏洞：票是一次性的、只活 60 秒、而且只发给已经登录的会话。

### 三条安全要求，一条都不能少

1. **票是一次性的。** 读出来就删，用 Redis 的 `GETDEL`，或者 Lua 脚本保证原子。
   不这么做的话，一张票被日志记下来就能重放。

2. **票只活 60 秒。** 它只是从一个 302 传到下一个 302，用不了那么久。

3. **`to` 参数必须校验。** 只允许以 `/` 开头、且第二个字符不是 `/` 的相对路径。
   放开的话就是一个开放重定向漏洞：`handoff?t=..&to=//evil.com`
   会把人送到别人的站上，而且是从你的域名跳过去的。

### 这套方案不需要动 CORS，也不需要动 SameSite

实施时**不要**去改 `WebMvcConfig` 的 `allowCredentials`，也不要把 `BUYER_SESSION`
的 `SameSite=Lax` 改成 `None`。两样都用不着，改了反而是拆自己的墙。

**为什么不需要 CORS**：两个域的 nginx 都有 `location /openapi/site/` 转本机 8081，
所以两边页面打的都是**自己域名下的相对路径**，浏览器眼里全是同源请求，
CORS 那套规则根本不参与。`WebMvcConfig` 的注释里已经把这条写清楚了：

> 正确的做法还是**同源**：`NUXT_PUBLIC_API_BASE` 留空，
> 让 nginx 上那条 `location /openapi/site/` 把请求转到本机 8081。

现在的 CORS 配置是 `allowCredentials(false)` 且只放 `GET/POST/OPTIONS`。
真去改成 `allowCredentials(true)`，白名单里任何来源都能带着买家会话发请求，
等于把 CSRF 的门打开 —— 而买家会话现在正是靠 `SameSite=Lax` 挡 CSRF 的。

**为什么不需要动 SameSite**：`SameSite` 判的是「站点」，不是「源」。
站点按 eTLD+1 算，`.com` 是公共后缀，所以：

```
kangchen.vclinker.com          ┐
buyer.kangchen.vclinker.com    ├─ eTLD+1 都是 vclinker.com
console.kangchen.vclinker.com  ┘   → 彼此是同一个「站点」，只是不同的「源」
```

也就是说主域和 buyer. 之间的跳转**根本不是跨站**，`SameSite=Lax` 一点都拦不住它。
handoff 那一跳是顶层 GET 导航，本来就在 Lax 允许的范围内。

⚠ 反过来说，这也正是**必须靠 host-only 而不能靠 SameSite** 来隔离的原因：
`console.` 和 `data.` 也在同一个站点里，`SameSite` 对它们同样不设防。
真正把买家会话挡在管理台之外的，是「不调 `setDomain`」这一件事。

**买家从收藏夹直接打开 `buyer.` 的订单页，但 buyer. 上没有会话。**
跳主域 `/login?back=...`。主域如果已经有会话，不用再输密码，直接发票交接回来。

**buyer. 上的 Cookie 过期了，主域的还在。**
同上，走一遍 `/login`，主域认得他，无感换回来。

**票在 60 秒内没用掉。**
过期作废，重新发一张。用户看到的最坏情况是「再点一次」。

## 怎么把人送到对的域名上

新建 `station-site/server/middleware/domain-split.ts`。

它干的事：看请求的 `Host`，把路径前面的语言前缀剥掉，判断这个路径该归哪个域，
不对就 301 跳到另一个域的同一个路径。

### 为什么写在 Nuxt 里，不写在 nginx 里

带语言前缀的路由（`/ja/products` 这种）是 Nuxt 在构建时用 `pages:extend` 钩子
自动生成的。要是把路径清单抄一份到 nginx，就有了两份会各自变旧的清单 ——
以后加一个买家页面，忘了改 nginx，那个页面在两个域上都能开。
写在 Nuxt 里，判断逻辑和生成路由的逻辑在同一个项目里，改一处就够。

### 它怎么知道两个域名叫什么

不写死。用两个配置项。

**线上现在的完整环境变量**（读的是 nssm 存的注册表键
`HKLM:\SYSTEM\CurrentControlSet\Services\wczl-station-site\Parameters` →
`AppEnvironmentExtra`，2026-09-08 核过，就这四条）：

```
NUXT_API_BASE=http://127.0.0.1:8081
NUXT_PUBLIC_SITE_URL=https://buyer.kangchen.vclinker.com
PORT=3000
HOST=127.0.0.1
```

所以这次是**改一个、增一个**：

| 配置项 | 现在 | 改成 | |
|---|---|---|---|
| `NUXT_PUBLIC_SITE_URL` | `https://buyer.kangchen.vclinker.com` | `https://kangchen.vclinker.com` | **改** |
| `NUXT_PUBLIC_BUYER_URL` | 没有 | `https://buyer.kangchen.vclinker.com` | **增** |

⚠ **`NUXT_PUBLIC_API_BASE` 现在压根没设，拆域时也别顺手加上。**
没设 = 浏览器侧走相对路径 = 同源，这正是埋点能工作的原因（见 nginx 那节）。
注意它和已设的 `NUXT_API_BASE`（SSR 侧直连后端）是两个不同的变量，别看串了。

写成配置而不是「主域前面拼个 buyer.」，是因为以后客户会带自己的品牌域名，
不一定按 `buyer.` 这个规矩命名。

### 三个必须跳过的情况

1. **接口不跳转**（`/openapi/site/` 开头的全部）。handoff 也在这下面，跳转了就废了。
2. **构建产物不跳转**（`/_nuxt/` 开头的全部）。
3. **只跳转 GET 和 HEAD。** 别的方法（POST 等）落到错误的域就直接 404。

第 3 条很重要：301 一个 POST，浏览器会把它改成 GET 重发，body 丢掉。
表现是「点了提交，什么都没发生」，而且非常难查。

## nginx

两个域的配置几乎一样：

```nginx
location /openapi/site/ { proxy_pass http://127.0.0.1:8081; ... }
location /_nuxt/        { proxy_pass http://127.0.0.1:3000; expires 1y; ... }
location /              { proxy_pass http://127.0.0.1:3000; ... }
```

**主域上不要拦 `/openapi/site/account/`。** 地址簿要用它。
（早先的草案里有这么一条，那是「主域零会话」方案留下的，现在作废。）

### ⚠ `NUXT_PUBLIC_API_BASE` 必须保持留空

留空 = 相对路径 = 同源，这是现在生产的配置，也是唯一能工作的配置。

埋点上报是这么拼地址的（`app/plugins/track.client.ts:167`）：

```js
const url = `${config.public.apiBase || ''}/openapi/site/pv`
```

上报走 `navigator.sendBeacon`，发的是 `application/json`。同源时不走 CORS 预检；
一旦 `apiBase` 被配成另一个域名，预检会挡下它，`SITE_VISITOR` Cookie 也不一定带得过去。

**要命的是 `sendBeacon` 拿不到响应** —— 前端连状态码都读不到。所以这件事出错时
**没有任何迹象**：页面完全正常，控制台干净，库里就是不再进数据。

搬到主域之后，只要主域的 nginx 也有 `location /openapi/site/` 转 8081，
`apiBase` 保持留空就对了。

**验收项**：前台发完之后打一次

```
POST https://kangchen.vclinker.com/openapi/site/pv
```

期望 **204**，且响应的 `Set-Cookie` 里有 `SITE_VISITOR`。这一条不过，埋点就是死的。

再加一条更省事的，一次验两件事：

```
curl -s https://kangchen.vclinker.com/ | grep canonical
```

`<link rel="canonical">` 要指向**主域**。这条同时验了 SEO 和埋点 ——
两者都由 `NUXT_PUBLIC_SITE_URL` 决定，那个变量设反了，canonical 会指向 buyer.
（SEO 直接受伤），埋点也会反过来只在 buyer. 上发。canonical 是这两个症状里
**唯一看得见的那个**，所以拿它当哨兵。

## 前端要改四个地方

0. **`app/plugins/track.client.ts`：只在「站点自己的域名」上发埋点。**
   理由和写法见下面「浏览量统计会受什么影响」第二条 —— 不改的话每个查订单的
   买家都会被永久算成两个访客。判据不要写死域名。

1. **购物车图标在 `buyer.` 上隐藏。**
   购物车存在主域的 localStorage 里，而 localStorage 是按域名隔离的，
   在 `buyer.` 上永远显示 0。留着只会让人以为东西丢了。

2. **`buyer.` 上所有「继续购物」类的链接**，必须写成指向主域的绝对地址。

3. **登录成功后，多走一步交接。**
   现在登录成功是直接跳页；改成先要一张票，把浏览器导到 buyer. 的 handoff，
   再由它 302 到最终目的地。

`SiteHeader.vue` 和 `ChatWidget.client.vue` **不用改** —— 两个域都能认人，
它们照原样工作。

## 搜索引擎那边

1. **`server/routes/robots.txt.ts` 改成认 Host。**
   ~~`buyer.` 上返回 `User-agent: *` 加 `Disallow: /`~~，主域返回现在这份。

   ⚠ **2026-09-10 改了：`buyer.` 上只 `Disallow: /account` 和 `/orders`（含 `/*/` 版），
   不再整站 Disallow。** 整站挡和下面第 4 条**互相抵消**——爬虫在发请求之前先读
   robots.txt，被 Disallow 的老地址它根本不会再抓，于是那条 301 永远不会被看到，
   老地址不是「权重转走了」，是「被挡住然后掉出索引」。站点搬家的通行做法就是别在
   robots 里挡旧地址。买家中心那两页仍然挡着，而且页面自己还带 `noindex`。

2. **`server/routes/sitemap.xml.ts` 只在主域服务**，`buyer.` 上返回 404。

3. **`NUXT_PUBLIC_SITE_URL` 必须改成 `https://kangchen.vclinker.com`。**
   这条漏了整件事就白做。canonical、hreflang、sitemap 里的绝对地址全靠它拼。
   还指着 `buyer.` 的话，主域上发出去的 canonical 会把 Google 又指回 `buyer.`。

4. **`buyer.` 上的老链接 301 到主域。**
   不用额外配，上面那个中间件顺手就做了。已经被收录的商品页权重能平滑转过去。

## 证书

新签这张也一样，到期时间对齐着一起换。

## 不做什么

- **不改会话模型。** `BuyerSession` 现有的「不透明令牌加 Redis」一个字不动，
  只是让两个域装同一把钥匙。
- **不放宽 Cookie 的 Domain。** 两份都保持 host-only。
- **不动购物车。** 它只在主域用。
- **不做会员价。** 定价那个方法（`repriceLines`）参数里没有买家，这次不加。

## 浏览量统计会受什么影响

三件事，第二件要改代码。

### 一、搬迁当天有一次断层（接受，不治）

老访客的 `SITE_VISITOR` Cookie 种在 `buyer.` 上，而 Cookie 是按域名隔离的
（`SiteVisitor.java` 里明确不调 `setDomain`），搬到主域后他们会被当成新访客重新计数。
180 天有效期的那批人全部重来一遍。

**能治，办法是给它加 `Domain=.kangchen.vclinker.com`。决定不治**，理由三条：

1. 只影响 UV 和回访率的连续性。**对「哪个商品值钱」这个核心用途没有影响** ——
   那看的是 PV 和询盘/订单的对照。
2. 放宽 Domain 之后，`SITE_VISITOR` 会**跟着每一张图片请求发到腾讯云 COS**
   （`file.` 子域 CNAME 到那边）。它不是凭据，拿到打不开任何东西，
   但那是一个 180 天稳定的访客标识，等于把「同一个人看了哪些图」送给第三方。
   为一次性的数字连续性付这个，不划算。
3. 真要改也**只能在搬迁那一刻改**，不能提前：改完浏览器里会同时存在两个同名 Cookie
   （老的 host-only 加新的 domain 域），而 `request.getCookies()` 里两个同名项的
   **顺序不保证**，`SiteVisitor.read()` 取的是第一个匹配 —— 等于把断层提前发生一次，
   还多一个不确定性。

**在管理台的浏览量页上标一句「X 月 X 日迁移域名，此前的 UV 不可比」就够了。**

### 二、⚠ buyer. 上不要发埋点（要改代码）

埋点插件现在**是记录**账号相关页面的（`track.client.ts:52-63`）：

```js
account: 'account',  orders: 'account',  'orders-id': 'account',
login: 'account',    register: 'account', ...
```

拆域之后 `/account`、`/orders` 在 `buyer.` 上，而 `SITE_VISITOR` 是 host-only ——
同一个人在主域一个 id、在 buyer. 另一个 id，**每一个查订单的买家都会永久变成两个访客**。
这不是搬迁当天那一次断层，是从此以后每天都在多算。

**做法：只在「站点自己的域名」上发埋点。**

判据是拿 `config.public.siteUrl` 的 host 和 `window.location.hostname` 比：

```js
const siteHost = (() => {
  try { return new URL(config.public.siteUrl).hostname } catch { return '' }
})()
// ⚠ 取不到就放行。统计少记几条可以接受，静默停止不行
if (siteHost && siteHost !== window.location.hostname) return
```

**不要写成「跳过 buyer. 域」。** 那是把一个会过期的事实钉进代码 ——
哪天主域再变一次，那行就成了一个静默的错误来源。

这个判据的好处是**它今天就已经是对的，不需要任何人记得改**：

| 时点 | `NUXT_PUBLIC_SITE_URL` | 判定 |
|---|---|---|
| 现在 | `https://buyer.kangchen.vclinker.com` | 前台就在 buyer. 上，**发** —— 和今天行为完全一致 |
| 拆域后 | `https://kangchen.vclinker.com` | 主域发，buyer. 上自动不发 |

也就是说改环境变量的同时，埋点行为自动跟着对，上线清单里不用多一步。

⚠ **配套前提：别把 `NUXT_PUBLIC_SITE_URL` 设成 buyer. 的地址。**
这次要同时新增 `NUXT_PUBLIC_BUYER_URL`，两个变量长得像，设反了的话埋点会
**反过来只在 buyer. 上发** —— 而且照样没有任何报错。

代价是「我的订单」「账号资料」这两页的浏览量从此不进统计。可以接受 ——
那是私密页面，不是营销页面，`pagetype: 'account'` 这一档本来也没人拿来做决策。

`/login`、`/register` 留在主域，照常统计，登录漏斗不受影响。

### 三、来源报表会脏一阵（不用改代码）

老域名跳新域名，会在 `u_s_pageview.referrer` 里留下一批
`buyer.kangchen.vclinker.com`。管理台那张来源表按主域后三段比对来打「站内」标签，
`buyer.` 和主域算同一个主域，所以会被正确标成站内。不用改代码，知道有这一批就行。
