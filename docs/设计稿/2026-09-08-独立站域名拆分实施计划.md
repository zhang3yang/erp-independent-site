## 阶段一：不碰冲突文件，现在就能做

### 1. `nuxt.config.ts` 加 `buyerUrl`

在 `runtimeConfig.public` 里，挨着现有的 `siteUrl`：

```ts
buyerUrl: process.env.NUXT_PUBLIC_BUYER_URL || ''
```

留空的默认值是有意的：本机开发不配这个变量，域名拆分逻辑就整个不生效
（见第 3 步的短路条件），本机还是单域，和现在一样。

**验**：`npm run build` 过。

### 2. `app/plugins/track.client.ts` 只在站点自己的域名上发埋点

代码用 wczl-erp-50 给的那段（设计文档「浏览量统计会受什么影响」第二条里有全文）。

位置：插件 setup 的最前面，和 `optedOut()` 那个提前返回并排，**不要放进 `send()` 里**
—— host 在整个页面生命周期里不会变，每次上报判一遍是白费。

**验**：本机 `NUXT_PUBLIC_SITE_URL` 不设 → `siteHost` 为空 → 放行，埋点照发。
这一步在本机和线上都是 no-op（线上现值 `https://buyer.kangchen.vclinker.com`
就等于当前 host）。

### 3. `server/middleware/domain-split.ts`

```
读 Host
若 siteUrl 或 buyerUrl 任一为空 → 直接放行（本机开发、单域部署）
跳过：/openapi/site/ 开头、/_nuxt/ 开头
只处理 GET 和 HEAD；其余方法落在错误的域 → 404
剥掉 /:lang 前缀（[a-z-]{2,5}），得到 basePath
BUYER_PATHS = [/login? 不，见下] …
```

买家路径清单（白名单，清单外一律归主域）：

```ts
const BUYER_PATHS = ['/account', '/orders']
```

⚠ **只有这两条。** 登录、注册、找回密码、验证邮箱**都在主域**
（用户 2026-09-08 确认，设计文档里有专门一节说明，别照直觉加进来）。

匹配规则：`basePath === p || basePath.startsWith(p + '/')`，
这样 `/orders/ORD001` 命中，`/ordersomething` 不命中。

**验**：`npm run build` 过；本机因为变量为空而短路，行为不变。
真正的验证在阶段四。

### 4. `robots.txt.ts` 认 Host、`sitemap.xml.ts` 只在主域服务

- `robots.txt`：当前 host 是 buyerUrl 的 host → 返回 `User-agent: *` + `Disallow: /`，
  否则返回现在这份。
- `sitemap.xml`：当前 host 是 buyerUrl 的 host → 404。

两个都要沿用第 3 步那个「变量为空就当单域」的短路，否则本机开发会拿到 404。

**验**：本机 `curl localhost:3000/robots.txt` 和 `/sitemap.xml` 和现在一样。

### 5. `SiteHeader.vue`：`buyer.` 上隐藏购物车图标

判据复用同一个「当前 host 是不是 buyerUrl 的 host」。

**验**：本机不受影响（短路）。

**这一阶段做完提交一次。** 五处改动在线上全部是 no-op —— 因为
`NUXT_PUBLIC_BUYER_URL` 还没设，所有逻辑都短路。这是有意的：
**代码可以先上，行为等环境变量到位再切换。**

## 阶段二：等地址簿提交后

### 6. `BuyerSession` 加 `adopt(response, token)`

只种 Cookie，不碰 Redis。

⚠ **不能调 `start()`** —— 它会先 `end()` 删掉旧令牌的 Redis 键再生成新的，
那样两个域就不是同一把钥匙了，而且表面看不出来（两边都能用，只是退出时
另一边不掉线）。设计文档里有专门一节。

顺便加一个 `isLive(token)`，handoff 里先验一遍：票发出后的 60 秒内如果用户
在另一边退了登录，就不该再种一个死 Cookie 上去。

### 7. 票的签发和兑换

新建 `session/BuyerHandoff.java`，两个方法：

| 方法 | 干什么 |
|---|---|
| `issue(token)` | 32 字节 `SecureRandom` → `station:buyer:handoff:<票>` = token，TTL 60 秒 |
| `redeem(ticket)` | Lua `EVAL`，读出来就删 |

⚠ `redeem` 必须是原子的一次性读取。`GET` 完再 `DEL` 中间有窗口，
一张票被日志记下来就能重放。

⚠⚠ **不要用 `GETDEL`（Spring Data 的 `getAndDelete`）** —— 这份计划原来就是那么写的，
实施时踩了：**`GETDEL` 是 Redis 6.2 才有的命令，而线上那台是 3.0.503、开发机是 5.0.14**。

后果是静默的：命令不认识 → Spring 抛异常 → catch 住返回 null → **交接永远失败**
（买家进买家中心显示未登录），**而且票不会被删**，一次性保护同时也没了。
日志里只有一行「兑换买家交接票失败：Error in execution」。

改用 Lua `EVAL`（Redis 2.6 就有，脚本在服务端单线程执行，原子性和 `GETDEL` 一样）：

```lua
local v = redis.call('GET', KEYS[1]) if v then redis.call('DEL', KEYS[1]) end return v
```

### 8. `BuyerAccountController` 加两个接口

| 接口 | 会话 | 行为 |
|---|---|---|
| `POST /openapi/site/account/handoff-ticket` | 要 | `requireBuyer` 之后 `issue(当前令牌)`，返回票号 |
| `GET /openapi/site/account/handoff?t=&to=` | 不要 | `redeem` → `isLive` → `adopt` → 302 到 `to` |

⚠ **`to` 必须校验**，否则是开放重定向：

```
只接受：以 / 开头，且第二个字符既不是 / 也不是 \
拒绝：//evil.com   /\evil.com   http://…   空
拒绝时的兜底目标：/
```

`/\evil.com` 那个也要拒 —— 部分浏览器把反斜杠当协议相对地址处理。

⚠ **不要挂在 `/sso` 上**，那是管理台 `SsoController` 的，只在 `console.` 域转发。

### 9. `useBuyer.ts`：登录成功后走一次交接

现在登录成功是直接跳页。改成：要一张票 → 把浏览器导到
`<buyerUrl>/openapi/site/account/handoff?t=<票>&to=<目标>`。

`buyerUrl` 为空（本机开发）时**跳过交接，按现在的方式直接跳页**。

### 10. `buyer.` 上的「继续购物」类链接改成主域绝对地址

**这一阶段做完提交一次。** 后端可以先发（加接口不影响老行为）。

## 阶段四：上线

按设计文档的上线顺序。每一步的验证点：

### 14. 签主域证书，nginx 加 server 块

放 `C:\nginx\cert\kangchen.vclinker.com\`。

**验**：`https://kangchen.vclinker.com/` 能开、证书链正常、地址栏不红。
此时两个域内容一样，用户无感。

### 15. 后端发版，重启 `wczl-station-console`

**验**：`GET /openapi/site/account/handoff?t=xxx&to=/orders` 用一张假票 →
应该被拒且不种 Cookie。顺便测 `to=//evil.com` → 拒。

### 16. 改环境变量，发前台产物，重启 `wczl-station-site`

改 `HKLM:\SYSTEM\CurrentControlSet\Services\wczl-station-site\Parameters`
→ `AppEnvironmentExtra`：

```
NUXT_API_BASE=http://127.0.0.1:8081                      ← 不动
NUXT_PUBLIC_SITE_URL=https://kangchen.vclinker.com       ← 改（原 buyer.）
NUXT_PUBLIC_BUYER_URL=https://buyer.kangchen.vclinker.com ← 增
PORT=3000                                                 ← 不动
HOST=127.0.0.1                                            ← 不动
```

⚠ **别加 `NUXT_PUBLIC_API_BASE`。** 它现在没设，浏览器侧走相对路径 = 同源，
这正是埋点能工作的原因。加上去埋点会静默死掉。

**这一步的四条验收，一条都不能省**（前三条的失败都是静默的）：

```
1. curl -s https://kangchen.vclinker.com/ | grep canonical
   → 必须指向主域。这条同时验了 SEO 和埋点（两者同由 SITE_URL 决定）

2. POST https://kangchen.vclinker.com/openapi/site/pv
   → 204，且 Set-Cookie 里有 SITE_VISITOR

3. curl -sI https://buyer.kangchen.vclinker.com/products
   → 301 到 https://kangchen.vclinker.com/products

4. curl -s https://buyer.kangchen.vclinker.com/robots.txt
   → 只有 /account 和 /orders 两条 Disallow，其余放行
   > ⚠ **这一条原来是「→ Disallow: /」（整站挡），已作废（2026-09-18 订正）。**
   > 2026-09-10 起买家域只挡那两条（判据见 `station-site/server/routes/robots.txt.ts`
   > 与 `deploy/nginx/tongling.conf`），写死整站 `Disallow: /` 的断言现在必然失败。
```

再手工走一遍：主域登录 → 点「我的订单」→ 落在 buyer. 且已登录 →
在 buyer. 点退出 → **回主域刷新，应该是未登录**（这一条验的是两个域
共用同一个 Redis 键，是整个方案的核心，必须亲手点一遍）。
