## 1. 这个模块补的是什么

**不是从零做 SEO。** 前台的 SEO 基建本来就相当完整：

| 已有的 | 在哪 |
|---|---|
| canonical + hreflang + og | `station-site/app/composables/useSeo.ts` |
| 每个商品每种语言都进 sitemap | `station-site/server/routes/sitemap.xml.ts` |
| robots.txt 按域区分买家中心 | `station-site/server/routes/robots.txt.ts` |
| 分语言的 seoTitle / seoDescription | `u_s_siteinfo.contentjson` 的 `i18n` 层 |

缺的是两件事：**让站长能改那些写死在代码里的规则**，和**验证码 / 统计代码的注入位**。

### 做了三块

1. **SEO 体检** —— 对现有数据做检查，不建业务表、不落库；
2. **sitemap / robots 可配置** —— 把写死的规则搬到库里，顺带修 sitemap 硬编码的 540 条上限；
3. **验证码 + 统计代码** —— 只存 ID，前台自己拼脚本。

### 刻意没做的，别当成遗漏

- **爬虫抓取日志。** 现有埋点走浏览器 `sendBeacon`（`app/plugins/track.client.ts`），
  **不执行 JS 的爬虫压根不上报**——`BotSniffer` 的类注释自己写着这是设计意图，
  不是缺陷。所以 `u_s_pageview` 里的 `isbot=1` 只有 Googlebot 这类会渲染 JS 的少数派，
  「哪个爬虫抓了哪些页」这件事**没法从现有数据得出**。要做得在 SSR 那一层新记一份
  （新表 + 中间件 + 清理任务）。
- **Google Search Console 拉数。** 服务器在腾讯云（`49.234.194.194`），
  连 GitHub 都不通，Google 的 API 更不用指望。**这一条要写死在设计里**，
  否则下一个人会花两天去接 GSC 才发现网络不通。
  所以「收录状态」只能靠站长自己在境外用浏览器看 GSC，而这个模块提供的是
  让 GSC 能验证通过的那个验证码。
- **301 重定向表。** 站刚上线，外链和收录都还没积累，一条都可能用不上。
- **Cookie 同意横幅。** 见 §6。
- **分片 sitemap。** 单文件规范上限 5 万条 URL，这个站离得很远。

## 2. 数据：`u_s_seo`

单行表（`id` 恒为 1），照 `u_s_storage` 的先例——那也是「一份全站配置、单行、
和站点档案分开」。

**为什么不加在 `u_s_siteinfo` 上**：那张表已经 17 列，注释在费力解释
「`currency` 和 `currencies` 只差一个字母但不是一回事」这类问题。而 SEO 配置的生命
周期不一样：验证码是一次性的、robots 是运营随时会动的，跟 `sitecode` /
`consolesecret` 那种一配就再也不碰的东西放在一起，语义上是错的。

```
收录     noindexall     tinyint   1=整站禁收录
        disallowpaths  varchar   额外 Disallow，逗号分隔（追加，不替换代码里的基线）
        robotsextra    varchar   robots.txt 末尾原样追加
sitemap sitemapon      tinyint
        sitemapmax     int       商品条数上限，默认 5000，硬上限 6000
        homefreq       varchar   首页/列表页 changefreq
        goodsfreq      varchar   商品详情页 changefreq
验证     googleverify / bingverify / baiduverify    只存验证码那个值
统计     ga4id / gtmid / baiduhmid                  只存 ID，不存代码
```

迁移脚本 `sql/station/migration/2026-09-08-seo-tools.sql`（幂等，含逐列的理由），
同时给 `operator` 角色加 `site:seo:query`，并登记迁移台账。
`01_station_schema.sql` 里也加了这张表（新建库不用跑迁移）。

### ⚠ 这张表的业务列基本都是公开的

那 13 个业务字段都会出现在匿名接口 `/openapi/site/info` 的 `seo` 子对象里。
**必须如此**：sitemap 和 robots 是 station-site（Nitro）生成的，不是后端生成的，
所以连 `sitemapmax` 这种看着像后端参数的东西也得发给前台。

于是这条约束是硬的：**将来要存 GSC 的 API key、第三方 token 之类的东西，
必须另建一张表。**

下发走 `SiteOpenService#publicSeo()` 的**逐列白名单**，不把实体直接序列化——
那是 `SiteOpenService` 类注释第 2 条。第一版就是直接扔实体的，于是
`updateUser`（管理台操作人的登录名）被发到了这个匿名接口上；`id` / `remark` /
`createtime` / `updatetime` 同样不外发。

### ⚠ `noindexall` 和 `u_s_siteinfo.status` 是两个独立的决定

不是同一个值的副本。`status=建设中/已停用` 会让前台**整个不对外**
（`SiteInfo#isOpen()` 只认「运行中」），那时候谈收录没有意义。
`noindexall` 管的是另一件事：**站开着、对访客正常，但先别收录**——
内容还没铺完就要给客户看的软上线阶段。

## 3. 后端

| 文件 | 干什么 |
|---|---|
| `domain/SiteSeo.java` | 实体 + 格式正则 + `defaults()` + `normalized()` |
| `domain/SeoAuditRow.java` | 体检取数的投影（一个商品 × 一种语言） |
| `domain/SeoIssue.java` | 一条体检问题 |
| `mapper/SiteSeoMapper.java` + `.xml` | 配置读写 + 体检取数 |
| `service/SiteSeoService.java` | 缓存、校验、保存 |
| `service/SeoAuditService.java` | 体检规则 |

接口三个：

```
GET  /api/seo        site:seo:query
PUT  /api/seo        site:seo:edit
GET  /api/seo/audit  site:seo:query
```

### 权限只有两个，不是三个

| 权限 | 谁有 | 能干什么 |
|---|---|---|
| `site:seo:query` | operator + admin | 看体检、看配置 |
| `site:seo:edit` | **只有 admin** | 改配置 |

体检给运营看，因为它就是运营的日常活——「哪个商品的日语标题还没填」，看完直接去改。
改配置里有 `noindexall` 那种一开就静默毁掉自然流量的开关，按管理台既有的分工
（operator 本来也没有 `site:station:edit`）归站长。

不加第三个 `site:seo:script`——统计代码已经只存 ID，和验证码不再是两个风险等级。

### ⚠ 查不到那一行不是错误

`SiteSeoService#current()` 在表不存在或行不存在时返回 `SiteSeo.defaults()`，
**永不抛异常、永不返回 null**。那份默认值的每一项都等于这个模块存在之前前台的原有
行为，所以「老库没跑迁移」和「跑了但没配」表现完全一致，不多出一种故障形态。

这一条是硬要求，不是防御性编程：`current()` 在 `/openapi/site/info` 的路径上，
那是**前台每个页面**都要打的接口。在那里抛异常等于「没跑迁移的老库整个前台白屏」。

### 体检的规则

只体检**已上架**商品（草稿和已下架对外不可见，它们的 SEO 问题不是问题）。

| 级别 | 检查 | 后果 |
|---|---|---|
| 高 | 商品某语言缺标题 | 前台回退默认语言 → hreflang 说是日语、`<title>` 是英文 |
| 高 | 商品某语言缺卖点**且**详情富文本也空 | meta description 空，摘要由 Google 乱截 |
| 高 | 语言开了但没有任何商品填了该语言标题 | hreflang 承诺了一个不存在的语言版本 |
| 高 | 装修内容缺某语言层 / 缺 seoTitle / 缺 seoDescription | 首页是权重最高的页 |
| 中 | 标题 >60 或 <10 字符 | 截断 / 不含关键词 |
| 中 | 卖点 >160 或 <50 字符 | 截断 / Google 往往不用 |
| 中 | 没填卖点但有详情富文本 | 描述从富文本剥标签截出来，句子通常是断的 |
| 中 | 同语言下多个商品标题完全相同 | 互相抢排名，可能判成内容重复 |
| 中 | 站点档案没填 domain | 不影响 canonical，但买家验证邮件和找回密码会直接报错 |
| 低 | 商品没有图 | og:image 回落到 logo，分享卡片全站一样 |
| 低 | 库里有译文但站点没开该语言 | 那份译文对外不可见，白填了 |

三条实现上的要点：

- **`left join`，不是 `inner join`。** 一个商品如果一条译文都没有也必须出现在结果里
  ——那正是最严重的一种问题，`inner join` 会让它安静消失、体检报「一切正常」。
- **体检读的是分语言的原始值，不走 `SiteOpenService` 那套「缺了退回默认语言」的合并。**
  合并之后每种语言都能取到值，于是「日语没配 seoTitle」会被回退机制掩盖——
  而那正是要查的东西。
- **标题重复一组只报一条。** 报 N 条的话，一个「所有商品都叫 Product」的站会瞬间刷出
  几百行，把别的问题全挤出视野。

### ⚠ 体检不落库

落库就会出现「已经改好了但还在报警」。一份需要人手动刷新才准的检查清单，
比没有清单更糟——因为它会被信。代价是每次打开扫一遍（两条查询，商品在几百量级）。

### ⚠ 有一件事体检不了，界面上必须说出来

**canonical / hreflang 指向的域名对不对。** 那个值来自 `NUXT_PUBLIC_SITE_URL`，
是 station-site 那个 Node 进程的环境变量，后端读不到。而按 `nuxt.config.ts` 的注释，
它设错时「只有 canonical 看得出来」——埋点会静默发到错的域上，页面完全正常。

所以体检结果里带一个 `notChecked` 数组（说明 + 一条 `curl` 命令），
**管理台上必须显示它**。一份体检报告最危险的地方不是漏报，
是让人以为「没报就是没问题」。

## 4. 前台（station-site）

### 新增 `server/utils/seoConfig.ts`

三处共用的取数 + 兜底 + **输出前校验**。抽出来的理由和 `hosts.ts` 一样：
同一套逻辑写三遍迟早有一遍漏改，而这里漏改的后果是「只存 ID」那条安全前提整个失效。

- 缓存 60 秒。注入 `<head>` 的插件在**每一次 SSR 渲染**时都要读配置，
  不缓存等于每个页面多一次后端往返。代价是改完配置最多等一分钟才生效——
  这和装修内容那句「保存后刷新立刻生效」不同，写在文件头免得被当成坏了。
- 取不到数返回默认值，**不抛异常**。
- `normalizeSeo()` 把格式不合法的 ID **一律置 null（不注入）**，并打一行 warn——
  一个被丢掉的 ID 在页面上没有任何症状，运营会以为接好了、一个月后才发现没数据。

### 新增 `server/plugins/seo-head.ts`

用 Nitro 的 `render:html` 钩子往 `<head>` 里注入验证码和统计脚本。

**为什么不是 `app.vue` 里 `useHead`**：`useSiteInfo()` 取数失败时会
`throw createError({ fatal: true })`。搬到 `app.vue` 就等于让根组件背上那个失败路径
——而统计代码取不到时，正确的行为是没有统计，不是整站 503。
这个钩子还顺带做到**一个页面文件都不用改**（验证码要在所有页面上，
包括 cart / login 那些不调 `useSiteSeo` 的）。

- **买家域什么都不注入。** 买家域只放 `/account` 与 `/orders` 两页（统计对它们没有意义）；
  而那些页面是每个买家各自的东西，把它们的地址发给 GA 不是这个功能该做的事。
  > ⚠ **2026-09-18 整理时订正**：这里原文写的是「那个域整站 `Disallow: /`」，**已经不成立**。
  > 2026-09-10 起买家域只挡 `/account` 和 `/orders`（`station-site/server/routes/robots.txt.ts`
  > 文件头写明了原因），整站 `Disallow: /` 的做法被撤销了。下面「怎么验」里那一条也已订正。
- **ID 在拼进 HTML 之前再过一次正则**（在 `normalizeSeo` 里），
  外加一次 HTML 属性转义。
- GA4 和 GTM 同时填时**两个都注入**，不替谁做决定——静默丢掉一个会让人对着
  一个「配了但数字不对」的界面查很久。管理台上有提示。

### 改 `server/routes/robots.txt.ts`

三层，从硬到软：买家域整站 Disallow（不可配）→ 基线 Disallow（不可配）→ 库里配的。

**⚠ 基线故意不搬进库。** 购物车、结账、我的询价、登录注册、账号中心不该被收录，
是这个站的结构性事实，不是运营偏好。搬进库的唯一效果，是某天有人把它们删掉，
然后结账页开始出现在搜索结果里。库里那两列是**加**，不是**替换**
（代码里还会去掉和基线重复的行，免得有人以为配错了去动基线）。

`noindexall` 打开时整个返回 `Disallow: /`，且不发 `Sitemap:` 那一行。

### 改 `server/routes/sitemap.xml.ts`

读配置；`sitemapon=0` 或 `noindexall=1` 时返回 404。

顺带修一个现有隐患：翻页圈数原来写死 `page <= 9`，配合 `size=60` 把 sitemap
封在 **540 条**，而那个文件的注释自己写着「真超过 500 个商品时要改成分片」。
现在圈数由 `sitemapmax` 算出来。**仍然不做分片**——5000 个商品 × 8 语言 ≈ 4 万条 URL，
还在单文件 5 万条的规范之内，所以 `sitemapmax` 在前后端都夹在 6000 以内。

### 改 `app/composables/useSeo.ts`

`noindexAll` 为真时多输出一个 `<meta name="robots" content="noindex,nofollow">`。

**⚠ 这一处和 robots.txt 那条 `Disallow: /` 是两件不同的事，缺一个都不算数：**
`Disallow` 管「别来爬」，`noindex` 管「爬到了别收」。被外链指到的地址不会被
`Disallow` 拦住，那时候只有 `noindex` 有用。这条分工在 `robots.txt.ts` 里已经为
cart/checkout 写过一遍，全站开关沿用同一条。

canonical 和 hreflang **照旧输出**，不因为 noindex 就撤：它们没有坏处，
而撤掉之后一旦把开关关回来，那几天 Google 眼里的站点结构是断的。

## 5. 管理台（station-console-ui）

```
views/Seo.vue              壳：三张卡的排布 + 权限门 + 配置只在这一层取一次
views/seo/SeoAudit.vue     体检
views/seo/SeoIndexing.vue  收录与 sitemap
views/seo/SeoTracking.vue  验证与统计
```

**为什么拆四个文件**：三块内容互不相干，全塞一个 `.vue` 会长成第二个
`Overview.vue`（1717 行，站点档案 / 存储 / 汇率 / 浏览量统计全在里面）。
不去重构那个文件（无关改动），但不在它旁边再长一个。

**配置对象放在壳里、两张卡共用。** 因为后端一个字段都不走 `coalesce`
（见 `SiteSeoMapper.xml`），保存必须送整份——共用一个对象就不存在「只送半份」的写法。
两张卡各持一份副本，保存时以壳里那份为底、盖上本卡的编辑，
免得一张卡的保存把另一张卡里还没提交的编辑一起送出去。

**打开「整站禁止收录」要二次确认。** 按破坏性操作对待：后果重
（已收录的页面几周内掉出搜索结果），而且**没有任何前台症状**。
关掉不确认——那是往安全的一边走。后端保存时也会打一行 warn，
因为这个值也可能是走 SQL 改的。

**预览是两个链接，不是页面内嵌。** 内嵌要么让后端去 `GET 127.0.0.1:3000/robots.txt`
（从 nginx 后面看，和公网访客看到的可能不一样，还得给后端新加一个「前台地址」配置），
要么浏览器直接取（跨域：管理台在 `console.` 子域）。两个 `target="_blank"` 的链接
看到的是**真的那一份**。

### 一处对现有文件的实质改动：`Goods.vue` 认地址栏参数

`?code=G001&lang=ja` → 直接打开那个商品的编辑框并切到那个语言页签。
体检的「去修」就是这么跳的。不加的话体检就是一张只会抱怨、给不出路径的清单。

打开后把参数从地址栏擦掉（`router.replace`）：不擦的话关掉弹窗再刷新会又弹一次。
`preferLang` 只在它真的是站点开着的语言时才用——地址栏来的值塞一个没开的语言进去，
页签会切到一个不存在的 tab。

### 菜单

`AppShell.vue` 的导航数组和 `router/index.js` 的路由表是**两份**，改一处不会带动另一处
（订单和客户那次就漏过这里）。两处都改了：站长工具去掉「还没做」的灰点，
图标从 `Odometer` 换成 `Compass`（原来和「站点概览」共用一个图标）。

§11 原本列了五个「留位置」模块，现在只剩**博客管理**和**营销管理**。

## 6. ⚠ 欧盟合规：同意横幅还没做

GA4 会写 `_ga` Cookie，在 ePrivacy 下属于「非必要 Cookie」，**欧盟访客要先同意
才能加载**。这个站的语言白名单是 `en/zh/ja/es/pt/ru/it/ko`——
其中 **`es` / `pt` / `it` 指向欧盟**。

2026-09-08 与用户确认：**这一轮只做开关，同意横幅下一轮再做。**
理由是同意横幅是一个独立的前台组件 + 8 语言文案 + 一套同意状态存取，
塞进站长工具会把这个模块拖成两倍大。

所以这是一条**明知故犯、被明确接受**的未完成项：

- 填了 GA4/GTM/百度统计就是**无条件加载**；
- **在同意横幅做出来之前，这几项不应该对欧盟流量开着**；
- 这句话写在管理台那个输入框旁边（`SeoTracking.vue` 的 `el-alert`），
  不只写在这份文档里——决定要不要开 GA 的是坐在那个页面前面的人，
  而他不会来看 spec；
- 将来做同意横幅时，改的是 `server/plugins/seo-head.ts`。

## 7. 出错时的行为

| 情况 | 行为 |
|---|---|
| `u_s_seo` 表或行不存在 | 后端返回全默认值，不是 500。和「跑了但没配」表现一致 |
| 前台取不到 `seo` 配置 | 按默认值走。统计不注入、robots 输出基线。**绝不 503** |
| ID 格式不合法 | 保存时拒绝并说明；输出时再卡一次，不合法不注入 |
| `sitemapMax` 越界 | 后端夹回 6000 并回填给界面（所以界面显示的是真正生效的值） |
| 体检遇到坏数据行 | 跳过并计数，末尾报「跳过 N 行」。一行坏数据不该让整张表打不开 |
| 体检取数失败 | 抛业务异常，**不返回空清单**——空清单看起来和「一切正常」一样 |
