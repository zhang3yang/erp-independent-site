## 先把话说清楚：这些名词是什么意思

这份文档反复出现下面几个词，先解释一遍，后面就不重复了。

**首页装修**
商家在管理台里有一个页面，填公司名、Banner 大标题、几条特色、关于我们的正文、
联系电话……填完保存，他自己那个独立站的首页就照着变。这件事叫「装修」。

**装修内容存在哪**
全部挤在数据库一格里：`u_s_siteinfo` 表的 `contentjson` 这一列，存的是一段 JSON
（一种带层级的文本格式）。商家点保存 = 整段重写一遍。

**首页由七块拼成**
从上往下：Banner、三栏特色、主推商品、能力介绍、关于我们、世界地图、询盘表单。
下面统称「区块」。

**分语言 / 所有语言共用**
一个站可以开好几种语言，访客切语言时整站文案都要跟着变。
所以文案类的东西每种语言各存一份；而电话号码、厂房照片这种，
本来就不分语言，存一份大家共用就行。文档里管前者叫「分语言的」，
后者叫「共用的」。

**「留空 = 用默认」**
商家不可能一次把所有格子填满。空着的格子，后端会拿一份内置的默认内容顶上，
所以页面不会因为没填就开天窗。

## 0. 一句话结论

**demo 挑出来的毛病基本都是真的，界面也画得很像。**

**唯一的大问题是：它为了做到那些效果，把「东西怎么存」整个换掉了。
而现在有 18 个网站文件在按老样子读这些东西，换了就得跟着改 18 个文件。
但它想要的效果，其实后端改一小段、再加两个清单就能拿到。**

一句话：**界面照它做，存法别照它做。**

## 3. 两件现在就能做的事

这两件跟重做没关系，各自单独就有价值，可以马上做。

> **✅ 2026-09-10 已经做完了，第 7 节的第一步就是这两件。**
> 具体改了什么、以及有一处没照 demo 做，见 [3.4 做完之后长什么样](#34-做完之后长什么样)。

### 3.1 「没权限就变灰」这个功能，只差最后一根线没接上

先说现在有什么毛病：保存按钮上挂了一个叫 `v-hasPermi` 的东西，
它的做法是**权限不够就把这个按钮从页面上抹掉**。
结果是——整页输入框照样能填能改，只有底下那个保存按钮不见了，
人吭哧吭哧填完一整屏才发现没地方存。

**这个毛病已经有人发现并且动手修了一半。**
`station-console-ui/src/views/Decorate.vue` 第 50 行，
上一层已经把「这个人能不能改」这个开关递下去了，
上面还写了一大段注释解释为什么不能用那个抹掉按钮的做法。

**但下一层根本没接。** `DecorateForm.vue` 里只接了「当前是哪个站点」和「重新读一遍」
两样东西（226-227 行），压根没接这个权限开关；
202 行和 206 行的两个按钮，还挂着那个会把自己抹掉的 `v-hasPermi`。

也就是说：上一层写的那段注释，描述的行为一天都没真的生效过。

demo 的第 6 条批评因此是准的，**但它不用等重做**：
把开关接上、按钮改成「还在但点不动」、顶上加一句说明为什么点不动，五行代码的事。

### 3.2 「点一下选图」的那个控件，我们已经有了

现在装修页里每个要图的地方都是一个空文本框，得自己粘一串网址进去。
demo 说这样不行，应该点一下从文件库里挑，我同意，原话是：

> 商家得先去文件页复制地址再回来粘 —— 而粘错了要到前台才看得出来。

**而这个挑图控件是现成的**：`station-console-ui/src/components/MediaPicker.vue`。
`station-shared/README.md` 结尾还专门留了一句「这个还没抽出来共用，等改到相关页面时再说」——
装修页正好就是那个「相关页面」。成本几乎为零。

顺带一提：`DecorateForm.vue` 里现在写着「站点是静态页，这里不做上传」，
**这句话已经过时了**。后端 `ConsoleApiController` 的 587 行和 626 行都有上传接口，
图片、视频都能传，还能分文件夹。

### 3.3 有个前提已经变了：ERP 那边不再用这个表单了

这个表单当初设计成「两个后台共用一份」——平台方在 ERP 里用一份，商家在自己的管理台用一份。
所以 `station-shared/README.md` 里写着「改这个目录的文件，两个项目都要重新构建验一遍」。

**现在 ERP 那边已经不用了。** ERP 前端里找不到任何引用，
对应的目录也不存在了；`views/site/station/index.vue` 第 5 行明确写着：
装修在站点自己那台机器的管理台上做，不在 ERP 里。

所以那条「要验两个构建」的额外成本，现在不存在，重做比 README 描述的便宜。
**但这件事得写进 README**，否则下一个人还会为一个不存在的规矩缩手缩脚。

## 4. 要改着做的地方

### A. 它换的那套存法，代价比它解决的问题大得多（最重要的一条）

demo 想让区块能拖着换顺序，于是把首页内容改成一个**有先后的清单**，
每一项是一块，带自己的开关、版式、内容。

听着挺对，但有个矛盾：**它自己规定了每种区块最多只能有一块**
（不能有两块「关于我们」，重复也没意义）。
既然每种就一块，那这个「清单」实际表达的只是**七块东西的先后顺序 + 各自开没开**，
根本不需要为它换掉整个存法。

**而换掉的代价在这儿。** 现在网站是这么读装修内容的：公司名就叫 `companyName`，
联系方式就叫 `contact`，导航就叫 `nav`，名字全都摆在最外面一层，拿来就用。
**有 18 个网站文件在这么读**（名单见第 6 节）——页脚、顶栏、SEO、
下单页、账户页、购物车、订单、商品列表、博客……

按 demo 那套改，这些名字全被挪进更深的层里，18 个文件得跟着一起改。
**而装修改版本来只该动首页一个文件。**

**建议拆成两件事看：**

- **界面**照 demo 分成「全站设置」和「首页区块」两组 —— 这个判断是对的；
- **存法**不用跟着分。想要的三件事各加一样东西就够了：
  - 顺序 → 加一个先后清单 `order`；
  - 开关 → 加一个「关掉了哪几块」的清单 `off`；
  - 每块自己的小设置（比如能力卡强调第几张）→ 加一个按块名索引的小抽屉 `blocks`。

具体长什么样见第 5 节。**一条硬要求：网站拉数据那个接口，返回的样子一个字都别变。**
底下怎么存是后端的事，网站除了首页那一个文件，不该知道有这回事。

### B. 世界地图那块，字段名早就说好了，别另起一套

首页最下面那张世界地图（从总部往各国拉弧线的那个），
**目前商家在管理台里配不了**，组件在用自带的天津 + 11 个城市顶着。
demo 把它补进了装修表单，这是补了一个真空白，优先级不低。

但字段名对不上。网站那边早就把接口形状写好等着了，
`station-site/app/composables/useSite.ts` 93-102 行原话：

> 后端 `/info` 现在不返回这一块，装修页里也还没有。……
> 等管理台加了这块装修、字段名对上，这里不用改就自动生效。

说好的形状是：总部和每个目的地都存**城市名 + 经纬度**。

demo 存的是**内置城市表里的第几个**（`hq: 0`、`dest: [3,7,12,17,19]`），
标题那一格还改了个名。两个问题：

1. 白白让后端多加一层翻译，把「不用改就自动生效」这个便宜作废了；
2. **存「第几个」是最脆的一种存法** —— 那张城市表里插一个城市，
   所有站点的地图一起跑偏，而且没人会察觉。

城市下拉框作为**填的方式**很好，但**存下去要存城市名 + 经纬度**。
另外必须能自己填城市：那张表里只有 20 个城市，
客户的总部十有八九不在里面。

### C. 「这个语言没填就退回英文」——现在后端不是这么干的

demo 的界面上有个提示：某块内容当前语言没填、但英文填了，就标一个「退回 en」，
意思是访客还是能看到英文版，不会开天窗。

**但现在后端不是这样。** 它的规矩是**整种语言一起论**：
这个语言压根没配 → 整份退回默认语言；
这个语言配了、只是里面缺了「关于我们」这一块 → **那一块不会去拿英文的**，
而是直接当成没填，用内置默认顶上（也就是那一块空着不显示）。

所以 demo 那个标签描述的是一个**还没实现的行为**。

顺带：同样这个错，**现在的表单也已经跟商家说过一遍了**——
`DecorateForm.vue` 74-75 行写着「某种语言没填的项，后端会退回默认语言」，
这句话是错的。

两种收法都行，**但必须先定一个**：

- 要么改后端，真做成一格一格地退回（顺带要想清楚：
  商家想让某个语言「就是不要导航」，怎么表达才不会被当成「没填」）；
- 要么把界面上的说法改成「这一块在这个语言下不会出现」，
  顺手把表单里那句错的提示也改了。

**不能让界面承诺后端做不到的事。** 这种不一致的表现是「预览跟线上不一样」，最难查。

### D. 十一种版式，工作量被低估了

demo 给六个区块各配了两三种摆法（错落的 / 三等分的、左图右文 / 图在上文在下 / 只有文字……），
加起来十一种。

听着是给商家自由，实际是：**每一种都是网站里一份新的排版和样式，
还要各自在手机窄屏上再调一遍。** 差不多把首页的样式量翻一倍。

而商家真正会用到的那个——「关于我们没配图时，文字卡退成整宽」——
**现在已经自动做了**（`index.vue:164`），根本不需要开关。

**建议第一版一种版式都不做**，钱花在排序、开关、选图、预览上。

### E. 预览：别在管理台里养第二份「假网站」

demo 为了做实时预览，在管理台里照着真网站的样式抄了 400 行 CSS。抄得很准，我核过。

**但真网站改一次样式，这份抄件就旧一次，而且旧了没人会发现。**
这种「两边各写一份、慢慢就不一样了」的事，
`station-shared/README.md` 里已经记过一次（同一段给商家看的说明，两个后台文案不一致）。

作为 demo 这么做完全合理。真做的时候建议换个思路：
**在管理台里开一个小窗口，里面装的就是真网站本身**，
商家边填、边把草稿推进去刷新。

好处：网站本来就是「改完刷新立刻生效、没有发布这一步」的，加个预览模式不算大改；
而且顺带把 demo 自己承认的三处假货一次解决——字体、真地图、真商品。

## 5. 建议怎么存

### 5.1 新格式长这样

在现在的格式上**只加四样东西**，原来的一律不动：

```jsonc
{
  "v": 3,

  // ↓ 新加的三样。都不分语言，后端原样转发给网站就行
  "order": ["hero", "bento", "products", "caps", "about", "reach", "inquiry"],  // 七块的先后
  "off":   ["reach"],                                                          // 关掉了哪几块
  "blocks": { "caps": { "accent": 1 }, "products": { "limit": 6 } },           // 每块自己的小设置

  // ↓ 所有语言共用的那些（现在只有 logo，以后能放更多）
  "logo":    "https://…",
  "hero":    { "image": "https://…" },        // Banner 背景图
  "about":   { "image": "https://…" },        // 关于我们的配图
  "contact": { "phone": "…", "email": "…", "whatsapp": "…" },
  "reach":   { "hq": { "name": "Tongling", "coords": [117.81, 30.94] },   // ← 第 4.B 条说的：存名字+经纬度
               "destinations": [{ "name": "Lyon", "coords": [4.83, 45.76] }] },

  // ↓ 每种语言各一份的那些
  "i18n": {
    "en": {
      "companyName": "…", "slogan": "…", "seoTitle": "…", "seoDescription": "…",
      "nav": [{ "title": "Products", "url": "/products" }],
      "hero":    { "title": "…", "subtitle": "…", "eyebrow": "…" },
      "highlights":   [{ "icon": "〰", "title": "…", "desc": "…" }],
      "capabilities": [{ "icon": "◆", "title": "…", "desc": "…" }],
      "about":   { "title": "…", "content": "…", "stats": [{ "value": "15+", "label": "…" }] },
      "contact": { "address": "…" },
      "reach":   { "title": "…", "lead": "…", "stats": [] }
    }
  }
}
```

### 5.2 后端只改一个地方

**现在的规矩**：共用那份先铺一层，语言那份盖在上面，**同名的一格，整格换掉**。

正因为是整格换，所以现在**能共用的只有 Logo 一个**——
因为 Logo 就是一根光秃秃的网址，不是一盒东西。
你想把 Banner 的背景图放进共用层，可语言层里只要有 `hero` 这一格
（哪怕里面只填了标题），整格连背景图一起被盖掉了。
`DecorateForm.vue` 文件开头那段「为什么只有 Logo 是共享的」说的就是这件事。

**改成**：如果同名那一格，两边装的都是一盒小项，那就**把盒子里的小项拼起来**，
不整格换。其余情况照旧。

```
共用的 contact 里有 {电话, 邮箱, WhatsApp}
语言的 contact 里有 {地址}
        拼起来 → {电话, 邮箱, WhatsApp, 地址}

共用的 hero 里有 {背景图}
语言的 hero 里有 {大标题, 副标题}
        拼起来 → {背景图, 大标题, 副标题}
```

就这一改，demo 的第 4 条（「更多东西可以所有语言共用」）就实现了。而且：

- **老数据完全不受影响**：老数据的共用层只有 Logo，是根光秃秃的网址，走不到「拼」这一支；
- 新加的 `order`、`off`、`blocks` 那三样，
  后端现在那段代码本来就是「不认识的东西原样搬过去」，
  **一行代码都不用加**，它们自己就会出现在给网站的数据里。

⚠ 有个副作用得写进注释：改成「拼」之后，某个语言**没法再删掉**共用层里的某一小项了
（只能覆盖成别的值）。目前没人有这个需求，但话要说在前面。

### 5.3 网站那边只改首页一个文件

给网站的数据长什么样**跟今天一模一样**，只是多了 `order`、`off`、`blocks`、`reach` 四样。
首页那个文件把七块拆成七个有名字的部件，按 `order` 挨个排、`off` 里的跳过。
**另外 17 个文件一个字都不用改。**

### 本机点了一遍，抓出三个只有点才会发现的问题

用一个假后端（跑在 vite 代理本来就指着的 8081，**没改项目里任何文件**）种了一份
v2 老数据 + 三个「未来版本写的」顶层键，然后在浏览器里从头点到尾。

**1. 两个图片格子绑错了字段 —— 背景图和配图永远是空的。**
把它们挪到共享层之后，输入框还绑在原来的 `form.hero.image` / `form.about.image` 上，
而那两个字段已经不存在了。表现是：老数据里明明有图，这一格却是空白；
更糟的是往里填会写回语言层，和整个改动拧着来。
**构建、编译、真值表全都发现不了这个** —— 只有打开那一页看一眼才知道。

**2. 保存条会被表格的表头压住，按钮点不动。**
`.deco-foot` 是吸底的，但没写 `z-index`，而 Element Plus 的表头单元格自带层级。
滚到某个位置，「保存装修」和「全部清空」同时被表头盖住——**看得见、点不着，
点下去什么也不发生**。这是早就有的毛病（「关于我们」「导航菜单」也各有一张表），
只是新的「全球布局」有两张表、页面更长，一滚就撞上。加一行 `z-index` 修掉，
七个页签逐个扫过所有滚动位置，现在都点得到。

**3. 换图要点两下，第一下看起来像坏了。**
挑图控件遇到「只能选一张」时，点另一张会弹「最多选 1 个」——
得先把当前那张点掉再点新的，而第一下只是选中框消失，多数人会以为控件坏了。
改成：只能选一张时，点另一张就是**换一张**。选两张以上的仍旧提示超额。
博客封面也用的这个控件，一起变好了。

## 10. 第三步：分组 + 排序 + 开关

**2026-09-10 做完两件（分组、排序开关），第三件（真网站预览小窗口）没做。**
两个项目都构建通过，站点侧和管理台侧各自在本机跑起来点过。

### 先做网站，再做管理台

顺序是有意的：**先让网站真的认 `order` / `off`，再给管理台做排序界面**。
反过来的话，中间那段时间管理台上排得动、首页纹丝不动——
用的人只会认为「这功能是坏的」，而且没有任何提示告诉他不是。

### 网站那边（station-site）

七个 `<section>` 一个字没动，只是外面套了一层按顺序循环，条件里多一个 `key === '…'`。

- **每块原来的显示条件都还在**：排序管的是顺序，「没配就不渲染」管的是有没有内容，两件事；
- **七个独立的 `v-if`，不是 `v-else-if` 链**——链要求相邻，而每块上面那段说明夹在中间，
  谁哪天删掉一条注释，链就会以「某一块无声消失」的方式坏掉，且构建不报错；
- **不认识的键丢掉、重复的去掉、漏掉的补在最后**。最后那条是为以后准备的：
  新增一种区块时，老站点存的 `order` 里没有它，不补的话它在那些站上永远不出现；
- **`limit` 夹在 1~24**。这个数来自装修 JSON（用户可写），
  直接透给接口的话一个 `size=99999` 就是把整库商品拉进首页。

顺手把两个写死的东西接上了：能力卡强调第几张（原来写死第 2 张）、
首页取几个商品（原来写死 6 个）。

### 管理台那边（DecorateForm）

一排七个平铺页签 → 左边两组、右边一块内容：

- **全站设置**：品牌与 Logo、导航菜单、联系方式、SEO 标题与描述；
- **首页区块**：七块，从上到下就是首页上从上到下，能拖、能用上下箭头挪、能用眼睛关掉。

几个具体决定：

- **拖放用原生的，不引第三方库。** station-console-ui 没有 `vuedraggable`，
  而共用目录里的组件不该逼宿主装依赖。七个固定条目，原生够用。
- **同时留了上下箭头。** 拖放在触摸屏上基本不可用，拖错一格也没法撤销；
  箭头一次挪一格，看得见、点得准。自动化测试也只能点箭头。
- **每条后面标状态**（「已隐藏」/「空 · 不显示」）。「填了没效果」是这一页最容易发生的困惑，
  在列表上直接看见就不用去猜。
- **`order` 总是写进 JSON，哪怕和默认顺序一样。** 默认顺序也是一种明确的选择，
  商家拖回原样之后下次打开必须还是原样。
- **原来挤在 Banner 页签下半截的「三栏特色」拆出来了**：它在首页上是独立的一屏，
  能单独关、能换位置。
- **「询盘表单」那块没有可填的东西**，但留了一格，因为它的顺序和开关要能改。
  里面写了一句提醒：关掉它之前记得改导航——默认导航的「Contact」指向的就是它。

### 点了一遍，又抓到一个

**侧栏钉住之后自己不会滚，矮一点的窗口够不着最下面几块。**
左边那一列是 `position: sticky`，十一条加起来 500 多 px。浏览器窗口矮一点
（没最大化的笔记本就是），最后两三块落在视口下面，而且**怎么滚页面都够不着**——
页面在滚，这一列钉在原地。加了 `max-height` + `overflow-y`，实测七块都点得到。

和上一轮那个 z-index 是同一类毛病：**在我的窗口尺寸下好好的，换个尺寸就废了。**

### 验过的

站点侧（跑起来抓 HTML 看真实先后）：

| 试的 | 结果 |
| --- | --- |
| 没配 order | 七块按默认顺序，和改之前一模一样 |
| `order=inquiry,about,hero,caps` | 这四块按这个顺序排在前面 |
| 同一份里没列到的 products / reach | 补在最后，没有消失 |
| `off=bento` | 那一块整块不出现 |
| `accent=0` / `limit=3` | 第 1 张能力卡变实心；3 张商品卡 |
| `order` 里塞 `__proto__`、`constructor`、重复的 `hero` | 垃圾键丢掉、重复去掉，页面正常 |
| `limit=99999` | 后端实际收到 `size=24`（夹住了） |

管理台侧：上下箭头能改顺序、眼睛能关掉、状态标签跟着变；

> **拖放验到了「差一步」**：合成鼠标事件驱动不了原生 HTML5 拖放（试过，`drag` 命令
> 报成功但没动），改成直接派发真的 `DragEvent` —— 结果是 `draggable="true"` 在、
> `dragover` 被 `preventDefault`（这一步决定它是不是合法落点）、`drop` 之后
> 「Banner」从第 1 条挪到了第 4 条（是摘出来再插进去，不是两两交换）。
>
> 也就是说**逻辑和属性都对，只剩「浏览器会不会把真实鼠标手势翻译成这几个事件」没验**，
> 而那是浏览器的标准行为。上线后顺手拖一次即可，不必当成风险项。

保存后写出的 `order` / `off` / `blocks` 和界面上一致，
`blocks` 只写非默认值（强调第 2 张是默认，就不写）；
没有编辑权限时 `draggable="false"`、三个按钮全禁用、点了不动。

## 11. 第三步收尾：真网站预览

**2026-09-10 做完。三个项目都构建通过，本机从头点到尾验过。第三步到此全部完成。**

### 撞到一个硬约束，方案跟着改了

原计划是「管理台里内嵌一个小窗口」。做之前查了一下发现走不通：

**主域的 nginx 发 `X-Frame-Options: SAMEORIGIN`**（`deploy/nginx/tongling.conf:197`），
而管理台在 `console.` 子域上——跨源，**浏览器直接拒绝内嵌**。

两条路：给预览那条路径单独放行一次 frame-ancestors（要改生产 nginx 并重载），
或者**另开一个窗口**（顶层窗口不受这个头限制，一行配置都不用动）。
按后者做了。以后想要左右分屏，再加 nginx 那一行就行，其余代码不用动。

### 推过去的是**算好的数据**，不是草稿 JSON

管理台先把草稿发给后端 `/api/site/content/preview`，后端用**和公开接口完全同一段代码**
算出合并结果，再把结果 postMessage 给预览窗口。

这一条是有意的：**合并规则只有后端那一份**。让预览页自己拿草稿去合，
那就是第二份实现，迟早和线上不一致——而症状是「预览里对、发出去不对」，最难查。
（这也是第 4.E 条说的「别在管理台里养第二份真站版式」的同一个道理。）

预览接口**不写库**，而且用 `require()` 不是 `requirePublic()`——
站点「建设中」时也要能预览，装修本来就是上线之前做的事。

### 安全上做了什么

- 只认 `?__preview=1`：普通访客的页面上这一整套连装都不装；
- **只收 `window.opener` 发来的消息**（比 `event.source`，不比 origin）——
  比对 origin 要求预览页知道管理台的域名，而它并不知道；比 source 更严：
  只有「把我打开的那个窗口」说的话才算数。本机试过：自己给自己发一条同样格式的消息，
  页面纹丝不动；
- 推送时 `targetOrigin` 写前台的确切地址，不用 `'*'`——那是还没发布的内容；
- 预览页 `noindex,nofollow`，**也不发埋点**（预览就开在主域上，
  不挡的话商家自己点几次预览，浏览量统计里就多几条 home）；
- 预览页右下角常驻一个「装修预览 · 这是还没保存的草稿」角标——
  它的地址就是首页地址加一个参数，不标一下没人分得清。

### 又是一个只有点才会发现的（第三个了）

**消息收到了、字段也改了、页面就是不动。**

原因是 **Nuxt 4 起 `useAsyncData` 默认 `deep: false`**（内部 shallowRef），
所以 `site` 是个**普通对象，不是响应式代理**——改它的字段不会触发任何重渲染。
两边代码都对，错在框架的默认值上，光读代码看不出来。

改法：`deep` 只在预览模式下打开。平时那样正好（站点信息取回来就不变，省一层 Proxy），
预览要的就是「推一份新的过来页面跟着变」。

顺带把一个**空的 `catch(() => {})` 改成会往控制台写一行**。
就是它让上面那个问题查起来格外费劲——连推送有没有发出去都看不到。
**空的 catch 比没有 catch 更难查。**

### 验过的

| 试的 | 结果 |
| --- | --- |
| 点「预览」 | 开出一个真前台窗口，地址是 `<主域>/?__preview=1` |
| 预览页 | 有角标、`robots` 是 `noindex,nofollow` |
| 在管理台改 Banner 主标题 | 停手约半秒后，预览窗口里的大标题跟着变了 |
| 在管理台把「能力介绍」整块关掉 | 预览里那一块消失 |
| 同时开着的**真实页面**（不带 `?__preview=1`） | 还是老内容、能力块还在 —— 草稿没漏到线上 |
| 假后端的保存日志 | 一条都没有 —— **预览全程不写库** |
| 在预览页自己给自己发一条同格式消息 | 被忽略，页面不动 |

### 一个已知的小别扭

预览窗口开的是 `<主域>/?__preview=1`，**没有语言前缀**。在管理台里切到日语继续改，
推过去的内容是日语的（后端按 lang 算好了），但那个页面的地址仍然是默认语言的首页，
所以页面里的链接（「查看产品」那几个）指向的是不带 `/ja` 前缀的地址。

**看内容没问题，点链接会跳到默认语言的页面。** 预览是用来看版式和文案的，
影响不大，所以先留着。真要修就是切语言时把预览窗口导航到 `/ja/?__preview=1`。

## 12. 第四步：挑着做的那两件

**2026-09-10 做完。** 第四步列了三件，做了两件，**版式那件按 [4.D](#d-十一种版式工作量被低估了) 那条没做**——
理由下面说。三个项目都构建通过，本机点过。

### 做之前先把前三步审了一遍，抓到一个真错

**左边那一列的状态标签会骗人。**

「三栏特色」在日语下没填、但英语填了——第二步改成**按项退回默认语言**之后，
日语页面上那一块**照样会出现**（显示英文内容）。而标签写的是「空 · 不显示」。

这正是我在 [4.C](#c-这个语言没填就退回英文现在后端不是这么干的) 里挑 demo 毛病的那件事：
**界面承诺了一个和后端不一致的行为**。而且方向更糟——商家会照着这句话
去排查一个根本不存在的问题。

改成三态：填了→不标；当前语言没填但默认语言填了→标「用 en 的内容」；
两边都没填→才是「空 · 不显示」。判据抽成 `blockHasContent`，
和前台那三个 `v-if` 一字对应。

顺带清了四处**已经过期的注释**（都在说「order/off/blocks 的编辑界面还没做」
「保存时变成 v2」这类第二、三步之前的话），以及一处小毛病：
人自己把预览窗口关掉之后，按钮还一直写着「预览中」。

### 一、Banner 轮播

管理台的「背景图」从一个格子变成一个**有序列表**（最多 5 张），带上下移和删除；
前台填两张以上就 5 秒切一张，底下带小圆点。

几个决定：

- **只有图在轮播，文案不轮播。** 一张图配一句话要给每张幻灯片单独存一份分语言的
  标题，那是 [4.G](#g-零碎几条) 里点名的「整个方案里最难存的一块」。
  而源站那三张图本来也共用同一句标题。真有商家要求再说。
- **存法只留一个键**：共享层的 `hero.images` 数组。不再同时写老的 `hero.image`——
  两个键指着同一件事，改了一个忘了另一个就是「首页背景图改不掉」。
  前台两种都认，老数据下次一保存自动归位。
- **og:image 用第一张**（分享到社交媒体时的预览图）。
- **最多 5 张**：轮播的图全都留在 DOM 里（切过去才下载的话第一次切换会白一下），
  再多就是拿首屏加载速度换一个没人看完的轮播。
- **跟随系统的「减少动态效果」**：勾了那个设置就不自动切，圆点还在，想看自己点。
  点了圆点也会停掉自动切——人正在挑一张看，图自己换走很烦。
- 圆点是**真按钮**：能点、能用键盘走到、读屏念得出「2 / 3」。
  标签只用数字，因为这一版没有「幻灯片」这个词的译文，
  而现编一个英文词摆在日语站上比数字更糟。

**只填一张（或一张都不填）时，这套东西全部不生效**：没有定时器、没有圆点，
DOM 和改造之前一模一样。

### 二、「留空 = 用默认」——那个默认到底是什么字

以前的提示是「留空用站点名称」「留空则使用默认导航：Home / Products / About Us / Contact」。
前者商家看不到到底是哪几个字；后者更糟——**那四个词是抄在前端的**，
而导航那一格的代码注释本来就写着「不预填默认值，预填了将来两边就对不上」，
提示文案自己违反了这一条。

现在**问后端要**：拿一份空的装修内容（`{}`）调第三步做的那个预览接口，
算出来的就是「什么都不填时前台显示什么」。同一段合并代码，不可能和线上不一致。

效果（本机实测的原文）：

- 公司名 → 「留空则显示「统领时代（本机假数据）」」
- Banner 主标题 → 「留空则显示公司名「Tongling Shidai」」
- SEO 描述 / Banner 副标题 → 「留空则用标语「Precision Airflow and Power Components」」
- 导航 → 「一条都不填的话，前台显示这几条：**Home / Products / About Us / Contact**」（从后端来的）

按语言各取一次、缓存住。取不到就退回原来那句笼统的提示，不影响填表。

⚠ 有一格**做不到**：「关于我们」的标题默认值不在后端，
是前台按访客语言选的一句内置文案（英文 About Us、日语「会社概要」）。
所以那一格只说清楚「留空则用内置标题（按访客语言自动切换）」——
写死一个 About Us 摆在日语站上就是错的。

### 三、版式（各区块两三种摆法）——没做

[4.D](#d-十一种版式工作量被低估了) 那条的判断没变，而且现在更成立：

十一种摆法就是前台十一份新的排版和样式，还要各自过窄屏，差不多把首页的样式量翻一倍。
而商家真正会用到的那个（关于我们没配图时退成整宽卡）**前台早就自动做了**。

**要做的话请指名一种**，比如「三栏特色改成三等分卡片」——
单独一种是半天的事，十一种是另一回事。

### 四、「预览里标出用了默认值的地方」——没做，而且现在没必要

demo 那个勾选框是给**它自己那份假预览**用的。第三步之后预览装的是真网站，
要标出来就得让前台知道哪些字来自默认值——那要么把默认值也传一份过去比对，
要么后端出一个「哪些键是默认的」清单，都是为一个开关铺一条新链路。

而上面第二件已经把同一个问题解决在了源头：**默认值直接写在输入框里**，
不用切到预览去找哪一块是灰的。

### 验过的

| 试的 | 结果 |
| --- | --- |
| 老数据（单张 `hero.image`） | 前台 1 层背景、没有圆点，DOM 和改造前一样；管理台里归一成 1 行 |
| 三张图（`hero.images`） | 3 层背景、3 个圆点、SSR 首帧是第 1 张 |
| 浏览器里连看 13 秒 | 2→0→1→2，每张停 5 秒 |
| 点第 3 个圆点 | 切到第 3 张，**自动切停掉**（再等 6.5 秒没动） |
| 管理台加一张、点上移 | 顺序跟着变；第 1 行的「↑」是灰的 |
| 保存后的 JSON | `hero.images` 两张按新顺序；**没有**旧的 `hero.image`；语言层里也没有 |
| 切到日语 | 默认值按语言各取一次（后端收到 2 次 `{}` 请求），不重复取 |
| 没有编辑权限 | 图片行的输入框、上下移、删除、「添加一张」全禁用；**「预览」也是灰的**（那个接口要 edit 权限，亮着只会点出 403） |

```powershell
                 -DestinationPath C:\build\live-console-src.zip
```

拉下来、覆盖上自己那几个文件、**逐文件 md5 证明只差自己那几个**，再打包。

### 预览为什么现在能内嵌了

第 11 节当时的结论是「另开窗口，因为主域发 `X-Frame-Options: SAMEORIGIN`」，
并且留了一句「以后想要左右分屏，再加 nginx 那一行就行，其余代码不用动」。这次就是加那一行：

```nginx
map $arg___preview $station_xfo       { default "SAMEORIGIN"; "1" ""; }
map $arg___preview $station_frame_csp { default "";           "1" "frame-ancestors 'self' https://console.DOMAIN"; }
```

主域的 server 块里把写死的那条换成这两个变量。**只有带 `?__preview=1` 的那一次请求**
换成 CSP，其余请求一个字都没变。

- 为什么不是「把 X-Frame-Options 改成放行」：这个头没有「允许某个别的域」那一档，
  `ALLOW-FROM` 早就没有浏览器认了。能表达「只让 console. 嵌」的只有 CSP。
- 为什么把 X-Frame-Options 一起收掉（取空串）而不是两条都发：两条都在时，
  认 `frame-ancestors` 的浏览器按 CSP 来——但那是要翻规范才敢确定的事，不如不依赖。
  靠的是「算出来是空串的 `add_header` 不发这条头」，这是 nginx 一直以来的行为（条件 CORS 也这么写）。
- ⚠ **康辰那台（`station.windows.conf.template`）主域原来一条 `X-Frame-Options` 都没有**，
  也就是说任何网站都能把那个商城整个 iframe 进去。这次顺手补上了 SAMEORIGIN + 预览放行，
  所以那份模板上这是**两条新加的头**，不只是改一个值。发版时留意。

前台那边只改了一处：`usePreview.ts` 原来只认 `window.opener`，现在是
`window.opener || (window.parent !== window ? window.parent : null)`——
另开窗口时是前者，内嵌时是后者。**比对 source 这条安全判据没有放松**：
仍然只收「把我放出来的那一方」发的消息，不比 origin（比 origin 反而更松，
同域下随便哪个页面都能冒充）。

**后端一行没改。** 合并规则是「同名键两边都是对象就合一层，其余整个覆盖」，
新增的都是对象里的新字段或者新的顶层键，正好落在这条规则里。
四个新顶层键要记得进 `KNOWN_ROOT_KEYS`——不进的话它们会被当成「不认识的键」
塞进 passthrough，表现是**保存一次之后这几项再也改不动**（passthrough 后写，会盖掉刚算好的值）。

### 「移除」不是「删除」

demo 里的 ✕ 是把那个区块实例删掉（它那套存法里区块是数组元素）。这里不能照抄：
`order` 里七块一直都在，`normalizeOrder` 还会把缺的补回来——那是**故意的**，
新增区块时老站点才不会永远看不到它。

所以 ✕ 映射到 `off`：内容留着，位置留着，从「添加区块」里加回来还是原样。
界面上说的是「移除 / 添加」，底下只有 `off` 一个状态，没有第二套。
眼睛图标因此也去掉了——它和 ✕ 是同一件事，摆两个只会让人猜它俩有什么区别。

⚠ 上下箭头改成按**看得见的那几块**算一格（`moveBlock`）。按 `order` 下标挪的话，
中间隔着一块被移除的，点一下箭头列表纹丝不动——它和那块看不见的换了位置。

### 幻灯片：为什么用 id 不用下标

每张的文案分语言、图和顺序不分语言，两边得对上。用下标的话，往中间插一张，
后面每一张的文案全错位；而这件事在管理台里看不出来，得到前台切到第二张才发现。

所以幻灯片是 `[{id, image}]`，文案按 id 存。删一张时**各语言里那一张的文案一起删**——
留着的话商家看不见、改不了，而它会一直躺在 JSON 里，下次生成的 id 撞上就诈尸。

老数据（`hero.images` 那种、甚至更老的 `hero.image`）载入时当场补 id，
补出来的那几张当然没有对应文案，于是全部退回整组共用的 `hero.title`——
和升级之前看到的一模一样。前台三种存法都认。

### 粉色数字卡：demo 抱怨得对，但不能照它改

demo 说这张卡不该从「关于我们」的数字亮点里借第一条——借的结果是同一个数字在挨着的
两屏里出现两次。这条成立，所以给了它自己的一格。

**但 demo 说的「留空则这张卡不出现」不能照抄**：老站点全都是靠借那一条撑起这张卡的，
改成不显示等于让所有人的首页悄悄少一块。所以是：填了用填的（「关于我们」那排数字
一条都不少），**留空还是照旧去借**（借走的那条就不在下面重复出现）。

### 前台那边动了什么

版式不是管理台自己能画出来的东西，四样里有三样要前台配合：

| 文件 | 改了什么 |
| --- | --- |
| `station-site/app/pages/index.vue` | `heroSlides`（三种存法归一）、每张自己的文案、眉标/按钮字、七块的版式 class、四块的区块标题回退 |
| `station-site/app/components/GlobalReach.vue` | `variant="list"`：不画地图，只留目的地那一列和底下的数字 |
| `station-site/app/composables/useSite.ts` | 类型跟上（hero.slides / slideText / eyebrow / btn1 / btn2、四个区块标题、blocks 里各块的 variant） |

⚠ **两边的版式清单必须一字不差**：管理台 `BLOCK_VARIANTS`、前台 `variantOf` 那几行。
对不上的表现是「在管理台里换了版式，首页纹丝不动」。认不出来的取值一律退回第一种，
而第一种就是「和以前一样」——所以一份坏数据的后果是页面照旧，不是版式乱掉。

⚠ 三等分版式下粉色数字卡不出现，所以那一条数字**不能再被借走**
（`bentoStat` 在这个版式下返回 null）。不判的话那条数字既不在这儿显示、
又被下面「关于我们」那排排除掉——凭空消失一条。

⚠ 「只列目的地」**省不掉**那 108KB 的国界数据：d3-geo 和 world-atlas 是 GlobalReach 的
静态依赖，进同一个 chunk。管理台那句提示写的是版面上的理由，不是体积。
真要省得把地图拆成异步组件。

## 16. 第七步：结构只存一份，文案按语言各存一份（2026-09-11）

### 要的是什么

> 页面区块结构、排序、图片全局只保存一份，所有语种共用；**只有文案、SEO 标题
> 描述这类文本，按多语言单独存储**。商家搭建页面一次，后续只需要切换语种翻译文字；
> 页面外观布局不变，同时各个语言页面拥有独立的 meta/H1，保证 hreflang 生效，
> 不会触发 Google 重复内容惩罚。

### 之前做到了哪、还差哪

v3（第 1～6 步）已经把**一半**做完了：图片（logo、Banner 幻灯片、关于我们配图）、
电话邮箱、地图点位、区块顺序 `order`、开关 `off`、每块的版式 `blocks` 都在共享层；
SEO 标题和描述本来就分语言。

差的是**那几张可重复的列表**——导航、三栏特色、能力、关于我们那排数字、
地图那排数字、粉色数字卡——它们**整条都还在语言层**。后果是结构会各语言分家：

- 同一个网址商家要填七遍，改一次要改七遍；
- 七种语言能排出七种不同的导航（条数、顺序、指向都可能不一样）；
- 加一条特色、换一个图标，得在每种语言下各做一遍；
- 某种语言少填一条，那个语言的首页上就真的少一块。

### 怎么改的：条目和文案拆两半，靠 id 对上

    共享层   "nav": [ {"id":"n1", "url":"/products"} ]      ← 有几条、指向哪、什么顺序
    语言层   "navText": { "n1": {"title": "Products"} }     ← 只有那几个字

六张列表全是这个套路（`nav` / `highlights` / `capabilities` / `hero.slides` /
`about.stats` / `reach.stats`），粉色数字卡是它的单格版
（共享 `bento.statValue` + 语言 `bento.statLabel`）。

**拼接在后端**（`SiteOpenService#compose`），所以前台拿到的还是
`nav:[{title,url}]` 这种老形状——station-site 除了幻灯片那一处，一行都没改。
放前台拼的话，「缺译文退回默认语言」那套规则就会有第二份实现，
而两份迟早不一致，症状是「管理台预览里对、发出去不对」。

### 两条不能破的规矩

1. **靠 id 对应，不靠下标。** 往中间插一条，下标就全错位，表现是「日语页面上
   每条文案都串了一格」。幻灯片第六步已经是这么做的，这次推广到全部六张表。
2. **文案袋子一律放在语言层的顶层**，哪怕它配的那个列表挂在别的键底下——
   幻灯片的袋子叫 `slideText` 而不是 `hero.slideText`，`about.stats` 的袋子叫
   `aboutStatText`。因为 `overlay` **只合一层**：顶层的袋子能和默认语言那份合一次，
   于是「这一条没译」能按条退回默认语言；藏在 `hero` 底下的话，整个袋子会被
   当前语言那份整个换掉——三张幻灯片译了一张，另外两张的字就没了。

   同一条道理还管着另一件事：**共享层和语言层在同一个父键底下必须各用各的键名**。
   `bento.statValue`（共享）/ `bento.statLabel`（语言）是对的；两边都写
   `bento.stat.xxx` 的话，语言层那个 `stat` 会把共享层那个整个换掉，数字就没了。

### 老数据：v1 / v2 / v3 都不用跑迁移

两边各做了一半：

- **后端**认「没有 id 的条目」——那是 v3 及更早的数据（条目里自带 `title`），
  `compose` 原样放行，页面显示和以前一模一样；
- **管理台**载入时把该共享的东西捞上来（`fillRows`），各语言的文案按**下标**
  对进新袋子（`textBag`）。条数按**最长的那种语言**算——少译的那种语言不该决定
  这个站有几条导航，按最短的算会静默丢内容。

商家点一次保存就自动归位。库里那份从此是 `v: 4`。

### 界面上的变化

- 那几张小表现在一行里有两种格子：**表头带「文」标记的那几格分语言**，
  其余所有语言共用。切语言时只有带标记的那几格会变。
- 标签上的小牌子分成两个：绿色的「条数和地址通用」、灰色的「名称分语言」。
- 左边那一列的状态标签跟着改了判据：「这一块出不出现」现在多半由共享层决定，
  「这个语言译了没有」是另一件事（`blockHasContent` vs 新加的 `blockTranslated`）。
  以前两件事是一件事，因为条目还在语言层。
- 加一行/删一行从 `ItemRows` 挪到了表单里：加要发 id，删要把**所有语言**里
  那一条的文案一起删掉，而那个组件只看得见当前这一种语言。

### 动了哪些文件

| --- | --- |
| `station-console/…/SiteOpenService.java` | `siteContent` 收口成一条路；新增 `compose` / `joinRows` / `joinNested` / `joinScalar` |
| `station-shared/DecorateForm.vue` | 六张表拆成共享条目 + 文案袋子；`fillRows` / `textBag` / `tidyRows` / `addRow` / `removeRow`；状态标签判据；v4 |

### 验过的

### 发版时注意

**后端必须先上。** 管理台先上的话，它存出来的 v4 数据会被老后端当成
「有 id 没文字」的条目——导航名字全空、特色卡只剩图标。顺序是
**后端 → 前台 → 管理台**（前台那一处改动依赖后端已经拼好幻灯片文案）。

### 没做的两件

- **地图上的城市名仍然不分语言**（总部和目的地）。它们是地名，写一次所有语言共用；
  真要按语言译的话，加一个 `destText` 袋子就行，结构已经支撑得住。
- **点开页面挨个格子看**这一步没做——`agent-browser` 在这台机器上起不来，
  改用了「模板绑定静态对账 + 往返脚本」两条替代路径。它们覆盖不到的只剩
  「格子绑对了字段但摆错了位置」这一类。

## 17. 第八步：草稿/发布、按钮链接、图片说明、机器翻译、未保存拦截（2026-09-13）

对着「1688 那类装修器」把这一页缺的东西过了一遍，挑了五件做。选的标准是
**改动小、现在就能用上**，不动 v4 的存法，也不碰「楼层化」那种要改存储结构的大件。

### 五件各是什么

| # | 做了什么 | 动了哪一层 |
| --- | --- | --- |
| 1 | Banner 两个按钮的**链接可配** | 纯前端（共享层 `hero.btn1Url` / `btn2Url`） |
| 2 | 幻灯片和关于我们配图的**图片说明（alt）** | 纯前端（语言层 `slideText[id].alt` / `about.imageAlt`） |
| 3 | **未保存改动拦截**（关页面 + 站内跳走） | 纯前端 |
| 4 | **一键机器翻译**（腾讯云 TMT） | 后端新接口 + 管理台 |
| 5 | **草稿 / 发布两态** | 迁移 + 后端 + 管理台 |

1、2 两件后端一个字没改：`hero`、`about` 在共享层和语言层都是对象，overlay 合一层就
把新键带过去了；`alt` 塞在文案袋子里，`joinRows` 本来就是把袋子里**所有**键拷进条目。

### ⚠ 语义变了：「保存」不再等于「上线」

这是这一批里唯一一个会让老用户愣一下的改动。

- 「保存草稿」写 `u_s_siteinfo.draftjson`，**contentjson 一个字不动**，前台照旧；
- 「发布到网站」在 SQL 里 `set contentjson = draftjson` 再把草稿置 NULL；
- 「放弃草稿」只清草稿 —— 这就是这一版的回滚：上一个已发布版本一直完整地躺在库里。

`PUT /api/site/content` 的**路径和方法都没变**，是有意的：后端和管理台分开发版，
万一只发了后端，老管理台点保存仍然存得下来（存成草稿），比 404 强得多。

两个值必须分清楚：`draftjson = NULL` 是「没有未发布的改动」，`'{}'` 是
「清空了但还没发布」。空串在 service 里被存成 `'{}'`，不是 NULL。

### ⚠ 发版顺序：后端 → 管理台。前台跟 1、2 两件一起，顺序不限

- **后端先上**：管理台要调 `/site/content/publish`、`/site/content/draft`、`/site/translate`，
  先发管理台的话这三个是 404。
- **迁移在后端之前跑**：`sql/station/migration/2026-09-13-decorate-draft.sql`。
  不跑的话 `selectSite` 那句 select 里多出来的三列直接报 SQL 错，**整个管理台都进不去**。
- **前台**（`station-site`）带的是按钮链接和 alt，和草稿/发布互不依赖。但它和管理台
  之间有一个短暂的错位窗口：管理台先上时商家能填链接，前台还没上就先不生效。

### 机器翻译：密钥复用 COS 那一对

腾讯云的 SecretId/SecretKey 是**账号级**的，一对通吃 COS 和 TMT，所以翻译不另存密钥
（多存一份就多一处泄漏面）。代价是**翻译能不能用取决于对象存储配没配**，
所以 `SiteTranslateService.explain()` 把错误码翻成「去哪儿填什么」，
而不是把 `AuthFailure.SecretIdNotFound` 摆给商家看。

⚠ 账号还要在腾讯云控制台**单独开通「机器翻译 TMT」**，没开通的表现是 `AuthFailure`。

没引官方 SDK，照 `CosClient` 那个先例手写 TC3-HMAC-SHA256 签名（`util/TmtClient.java`）：
后端是在服务器上打包的，那台机器网络受限，多一个依赖就多一次构建失败的可能。

界面上只填**空格子**，已经填了字的一个都不覆盖——商家斟酌过的那句话不能被一次误点冲掉。

### 链接的安全边界在前台，不在管理台

`hero.btn1Url` 会原样进 `href`。管理台那个 `linkError()` 只是让人当场看见填错了，
**真正挡住 `javascript:` 的是 `station-site/app/pages/index.vue` 的 `heroLink()`**——
库里可能有老数据，也可能有人绕开界面直接调接口。两边认的写法必须一字不差地一致。

### Banner 背景图从 CSS 背景改成真 `<img>`

alt 要有落脚处，而 `background-image` 在搜索引擎眼里根本不存在——首屏那张往往是
厂房、产线、主打产品，正是最值得被搜到的一张。顺带给第一张加了
`fetchpriority="high"`，LCP 比等样式算完再开始下载早一截。
排版靠 `object-fit: cover` 顶替 `background-size: cover`，视觉一致。

### 退回的粒度是「条目」，不是「字段」

这次被真值表当场抓出来的一条（我一开始断言错了）：`overlay` 只合一层，
所以文案袋子合的是「有没有 s1 这一条」。**日语一旦给了 s1，s1 那整个小对象就被日语那份
整个换掉**，里面缺的字段不会再逐个退回英文。

对 alt 来说这是对的：一句英文说明配在日语页面上，对读屏用户和 Google 图片都是错的信号，
