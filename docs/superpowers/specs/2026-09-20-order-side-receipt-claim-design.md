# 回款认领搬到销售订单详情

日期：2026-09-20

## 1. 要解决什么

客户打款分两种：

- 打款时带了订单号（平台下单、客户备注了单号）。财务录流水时就知道是哪张单。
- 直接打款，不知道是哪张单。要有人把这笔钱和订单对上，这一步叫「认领」。

现在认领在「财务管理 → 资金流水」页做：认领弹窗列全店所有未收满的订单，业务员从里面挑。
订单不按业务员过滤，容易认到别人的单上。

目标：认领改到「销售订单详情 → 收款流水」页签里做。业务员打开自己的订单，
从待认领的打款里挑一笔认到本单。每笔打款一行，认错了自己能撤回。

## 2. 不变的东西

- 状态机不变：草稿 → 待审核 → 已审核 → 已完成，驳回回到已驳回。
- 已收金额只在财务终审通过（已完成）时回写，订单侧没有任何直接写已收金额的入口。
- 一笔流水只绑一张订单。**一笔打款对应多张订单时，财务按订单拆成多笔流水录入**，这是录入规范。
- 只能认领与订单**同币种**的流水。系统不做汇率换算，跨币种认领另行设计。
- 不加表、不加列、不加菜单权限。认领与撤回都沿用 `finance:transaction:claim`。

## 3. 状态流转（销售回款）

| 场景 | 流转 |
| --- | --- |
| 财务建流水，没填订单号 | 草稿 → 提交 → 待审核（待认领）→ 业务员在订单里认领 → 已审核 → 财务终审 → 已完成 |
| 财务建流水，填了订单号 | 草稿 → 提交 → **直接已审核**（认领人记为提交的财务）→ 财务终审 → 已完成 |
| 撤回认领 | 已审核 → 待审核，清空订单号、业务摘要、认领人。只有认领人本人或有 `finance:transaction:audit` 的人能撤。已完成的不能撤，走退款 |
| 财务驳回已认领的回款 | 已审核 → 已驳回，**同时清空绑定**。重新提交后要重新认领（或财务改单时重新选订单） |

驳回时清空绑定的理由：提交改成「填了单号就自动绑定」以后，驳回如果留着旧单号，
财务不改就重提，会原样绑回那张认错的单。清掉等于回到「必须重新认领」，与原来的语义一致。

## 4. 后端

全部在 `FinanceTransactionServiceImpl` / `FinanceTransactionController`，路径挂在 `/finance/transaction` 下。

### 4.1 待认领流水查询

`GET /finance/transaction/unclaimed?currency=USD`，权限 `finance:transaction:claim`。

条件：业务类型销售、收支方向收入、状态待审核、币种等于入参。不看订单号是否为空：
改造前已经填了单号、卡在待审核的老数据也要能从订单里认领走，列表把财务预填的单号一并带出来给业务员参考。
扫全部资金流水月表，按交易时间倒序。

### 4.2 认领（接口不变，服务层加两条校验）

- 订单是草稿的拒绝。与「可回款订单」下拉排除草稿的规则对齐，放在 `requireSalesOrder` 里，建单预填单号同样受限。
- 归属：没有 `order:sales:all` 的人只能认领到自己名下（`staffcode`）的订单，用 `OwnershipScope.requireOwn`。
  订单详情本身就是按归属过滤的，这条是防直接调接口。

### 4.3 撤回认领

`POST /finance/transaction/{code}/unclaim?tableSuffix=yyyyMM`，权限 `finance:transaction:claim`。

- 只有客户回款（销售 + 收入）有这一步。
- 状态必须是已审核。
- 认领人本人（`completeuser`）或有 `finance:transaction:audit` 权限的人才能撤。
- SQL：`updateTransactionStatus` 用 coalesce 保留原值，清不掉字段，新增 `clearClaimBinding`
  一条语句把 `bizcode / bizsummary / completeuser` 置空并改状态，驳回已认领回款时复用。

### 4.4 提交时自动绑定

`submitTransaction`：客户回款且 `bizcode` 非空时，校验订单存在、非草稿非取消、币种一致、不超待收，
通过则直接进已审核，认领人记为提交人。超过待收直接报错，提示财务改金额或清空订单号交给业务员认领并确认超额。

## 5. 前端

### 5.1 销售订单详情「收款流水」页签

- 页签顶部加「认领打款」按钮：有 `finance:transaction:claim` 权限，且订单非草稿、非已取消时显示。
- 弹窗是一张表，列同币种的待认领流水：流水号、交易时间、收款账户、打款人、对方文本、凭证图、金额、财务预填单号、录入人。
  每行一个「认领到本单」按钮。金额超过本单待收时弹确认框，文案与原财务页一致，确认后带 `allowOverpay`。
  认领成功后该行从弹窗消失，页签刷新。
- 页签表格加操作列：状态为已审核，且认领人是我或我有审核权限时，显示「撤回认领」。
- 页签底部提示改为：认领在这里做；补录、改金额去财务。

### 5.2 资金流水页

- 去掉「认领」按钮和认领弹窗，以及只为它服务的函数。
- 「提交认领」改成「提交」。提交成功的提示按有没有单号分两句。
- 建单表单的订单号提示改成：知道是哪张单就选，提交即绑定；不知道留空，由业务员在订单详情里认领。
  加一句：一笔打款对应多张订单时按订单拆行。
- 待审核的客户回款在状态列显示为「待认领」，让财务一眼看出还没人认。

- 提交：填了单号自动进已审核并记认领人；超待收拒绝；订单是草稿拒绝。
