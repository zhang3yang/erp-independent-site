# 引导式下单（下单向导）设计

2026-09-28。照嘉立创 PCB 在线下单页的交互，给独立站做一个「按参数选配、每一单都像定制」的下单入口。
最初用一个静态原型（用户桌面 `引导式下单原型.html`）确认布局，功能上线后已删除，以线上为准。

## 用户已定的四件事

| 问题 | 决定 |
|---|---|
| 面向谁 | **两种都要**：第一问「个人 / 企业」，后面的参数组按它显隐 |
| 价格 | 先显示**询价**；每个选项预留 `price` 字段，现在不计算 |
| 参数怎么维护 | **管理台可配置**；第一版预置按摩仪那套 |
| 上哪个站 | 做成**开关**，三站同一套代码，先开法国站 |

## 形状

```
前台 /configure（带语言前缀同样可用：/en/configure）
┌──────┬────────────────────────────┬──────────────┐
│步骤条│ 分组1：字段…（卡片/按钮/色块…）│ 配置明细      │
│(滚动 │ 分组2 …                       │ 数量合计      │
│ 高亮)│ …                             │ 预估总价=询价 │
│      │ 最后固定一组：联系方式与收货   │ 检查 / 提交   │
└──────┴────────────────────────────┴──────────────┘
```

「联系方式与收货」不进 schema，直接复用结算页那套字段（姓名、邮箱、公司、电话、国家、地址、
运输倾向、付款倾向、备注）。理由：那是下单接口的固定入参，放进可配置的 schema 里只会让人把它删掉。

## 存储

新表 `u_s_orderwizard`，一个站一行：

| 列 | 说明 |
|---|---|
| `sitecode` | 主键，一个部署一个站 |
| `enabled` | 前台开关。0 = 入口不出现、`/configure` 404、提交被拒 |
| `schemajson` | 向导定义，见下 |
| `updateuser` / `updatetime` | |

不做草稿/发布两态：向导改动的影响面比首页装修小（不开开关就没人看得到），第一版保存即生效，
管理台上有「在前台预览」链接。

订单加一列 `u_s_order.wizardjson`：提交时那份选择的**快照**（带文字，不是只存编码）。
schema 以后会改、选项会删，订单里必须留下「当时客户看到并选了什么」。

## schema

```jsonc
{
  "version": 1,
  "title": { "fr": "...", "en": "...", "zh": "..." },   // 页面标题，缺语言按 当前→en→默认语言→任意 回退
  "lead":  { ... },
  "groups": [{
    "code": "basic",
    "title": {...}, "sub": {...},
    "showIf": [ { "field": "audience", "in": ["business"] } ],   // 条件之间是 AND
    "fields": [{
      "code": "mode",
      "type": "cards | options | swatch | number | text | date | goods",
      "multi": false,
      "required": true,
      "title": {...}, "help": {...}, "hint": {...},
      "showIf": [ ... ],
      // number：min/max；goods 非空时，这个数就是该商品的下单数量（主机台数）
      "min": 1, "max": 99999, "goods": "EB-UNIT-01",
      // goods 类型：从哪个多选字段取「选了哪些商品」，再按每个商品自己的型号填数量
      "source": "garments",
      "options": [{
        "code": "oem",
        "title": {...}, "desc": {...}, "badge": {...},
        "icon": "🏷️", "image": "https://...", "color": "#15181C",
        "hidden": false,          // 对访客隐藏（工厂还没确认的选项先藏着）
        "needs": [ ... ],         // 不满足时显示但置灰，提示原因
        "moq": 100,               // 选了它时 goods 字段数量合计的下限
        "price": 0,               // 预留，现在不计算
        "goods": "EB-BOOT-01",    // cards 选项对应的商品（goods 字段靠它出型号）
        "sets": { "plug": "EU", "certs": ["CE"] }   // 选中时顺带改别的字段（目的国家 → 插头、认证）
      }]
    }]
  }]
}
```

### 答案格式（前台提交 / 后端校验的同一份）

| type | 值 |
|---|---|
| cards / options / swatch 单选 | `"oem"` |
| 多选 | `["boot","arm"]` |
| number | `50` |
| text / date | `"..."` / `"2026-11-30"` |
| goods | `{ "EB-BOOT-01": { "M-TOUTENSEMBLE": 10, "L-TOUTENSEMBLE": 20 }, "EB-ARM-01": { "": 5 } }`（没有型号的商品用空串键） |

## 提交链路

复用 `POST /openapi/site/order`（同一个限流、蜜罐、回执邮件、回执页），请求体多一个 `wizard` 对象：
`{ "answers": {...} }`。

有 `wizard` 时 **忽略请求体里的 `items`**，后端 `OrderWizardService.resolve()`：

1. 取已启用的 schema（没开 → 400）
2. 按顺序求值显隐：分组 `showIf` → 字段 `showIf`；看不见的字段答案丢掉
3. 逐字段校验：必填、选项存在且未隐藏、`needs` 满足、数值范围、文本长度 ≤ 1000、日期格式
4. goods 字段：每个商品必须上架、型号必须存在且可选（`selectPublicOne`），数量是正整数
5. `moq`：选中的选项带 moq 时，goods 数量合计不得低于它
6. 产出**订单行**（goods 字段的每个 商品×型号，number 字段挂了 goods 的那一行）和**快照**

然后照常 `SiteOrderService.submit()`：价格、商品名仍由服务端现查，订单还是「待确认」。
快照写进 `wizardjson`，商家通知邮件里附上快照文字。

快照每条：`{ "group", "field", "value", "code", "raw" }`，文字按**站点默认语言**和**中文**各存一份
（`label` / `labelZh` …），管理台优先中文。

## 前台入口

- `/openapi/site/info` 下发 `wizard: { enabled, title, goods: [...] }`（goods = schema 里挂到的商品编码）
- 顶栏：开了就多一个「在线定制」按钮
- 商品详情：该商品在 `goods` 里时，加入询价单旁边多一个「定制下单」链接到 `/configure`

## 管理台

左侧菜单「引导下单」（权限复用 `site:station:*`）：

- 开关、前台预览链接、恢复预置模板
- 树形编辑：分组 → 字段 → 选项，文案按站点语言分页签
- 条件编辑：字段下拉 + 值多选
- 商品挂接：从本站商品下拉选
- 高级：整份 JSON 导入 / 导出

订单详情多一块「引导下单配置」，把快照逐条列出来。

## 刻意不做（第一版）

- **访客上传 logo 文件**：那是一个匿名写文件的公网接口，要限流、限类型、防灌盘，单独做。
  第一版在 logo 字段的说明里写「提交后回复确认邮件附上 logo」。
- **实时计价**：价格全是 0，`price` 只存不算。
- **草稿/发布**：见「存储」。

## 预置模板按站点对应（2026-09-28 补）

三个站卖的东西不一样，只有一份模板时统领点「载入预置模板」会被换成法国站那套。现在
`OrderWizardService.PRESETS` 登记每份模板给哪些站用（按站点编码）：

| 模板 | 文件 | 站点 |
|---|---|---|
| massager 按摩仪整机 | `order-wizard/massager-template.json` | 法国站 DLZ2049739702 |
| parts 零部件与加压套件 | `order-wizard/tongling-template.json` | 统领 DLZ2049684105 |
| tubing 硅胶管按图定制 | `order-wizard/kangchen-template.json` | 康辰 DLZ2049683802（2026-09-29 补） |

管理台：有本站对应模板时是分裂按钮，主按钮一键载入本站那份，箭头里能换别的；一份都对不上
只给下拉，不替人挑别家的。新站要有自己的模板：加一个 JSON + 在 PRESETS 里加一行。

## 预置模板（法国站）

按原型的六组，文案 fr / en / zh / es / ru / ja 六语。以下选项预置为 `hidden: true`，工厂确认后在管理台打开：
深灰 / 电光蓝 / 指定色号面料、刺绣、硅胶标、定制彩盒、电池版主机、英规 / 澳规插头。
依据：库里工厂产品线只有欧规和美规适配器（12030501 / 12030502）；电池 26650 11.1V 5000mAh（12010701）
是零件，没有「电池版主机」这个成品。

## 预置模板（康辰）

2026-09-29 补。康辰定位「硅胶件按图定制」，前台当时只上架两款管（12010304 4 腔单排、12010305 8 腔双排，都按米卖），
所以模板围绕这两款管：基本信息（目录规格 / 按图定制 / 新开模、用途、目的国）→ 管型与米数 →
定制参数（仅按图定制 / 新开模：材料等级、邵氏硬度、颜色、表面、尺寸说明必填、整卷或切段、图纸/样品）→
认证与文件 → 包装、打样与交期。文案 zh / en / es / pt / it / ko / ja 七语（康辰前台开的语言）。

- 起订量挂在「直接做大货」上（合计 ≥ 500 米，同商品页 moq）；「先打样」不限米数。
- 用途联动材料等级（食品 → 食品级、医疗 → 医疗级），目的国联动认证（美 → FDA + RoHS，欧 / 英 → RoHS + REACH）。
- 认证选项只列站点「认证文件」里说得出的：RoHS、REACH、FDA、LFGB、ISO 9001；能给哪些以报价书面确认。
