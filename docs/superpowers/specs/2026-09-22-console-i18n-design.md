# 管理台多语言（站点设置 →「管理台语言」+ 顶栏个人切换）

2026-09-22

## 这件事是怎么来的

法国站（esvafit）交付给客户之后，管理台的假设塌了一半：**它原来默认「用它的人都懂中文」**。
站长是外国人，他点开看到的是一整屏中文——左边十一个菜单、每一栏的说明、每一个按钮。
他不是「看得慢一点」，是根本不知道哪个按钮是保存。

而我们自己的业务员同时还在用同一个管理台，他们要看中文。

所以这件事的形状是「**同一套界面、两个人各看各的语言**」，不是「把管理台翻译成法语」。
这一条决定了下面所有的设计。

## 两层：站点默认 + 每个人自己的选择

| | 存在哪 | 谁改 | 影响谁 |
|---|---|---|---|
| 站点默认语言 | `u_s_siteinfo.consolelang` | 站长，在「站点概览 → 站点设置 → 管理台语言」 | **第一次**进来、还没自己选过的人 |
| 个人选择 | 浏览器 `localStorage['station-console-lang']` | 每个人，在顶栏右上角 | 只有他自己 |

**少了第二层**：站长切成法语的那一刻，所有业务员的管理台一起变法语。
**少了第一层**：法国站长第一次进来还是一屏中文，而他未必找得到那个下拉。
两层都要，这是这个功能的全部要点。

一个推论写进了代码：站点设置里改完默认语言之后，**只有「没自己选过语言」的人**当场跟着变
（`Overview.vue` 的 `save()` 里那个 `if (!localeChosen.value) resetLocale(...)`）。
自己选过的人一个字都不该动——他只是顺手帮站长改了个默认值。

## 「两块对不上」——以及为什么这不是 bug，但界面确实错了

上线当天就被问了一次：站点设置里写着 `Français`，右上角却是「中文」。

**它们本来就是两个值**（站点默认 / 我自己选的），不一样是允许的，上面那张表就是这么设计的。
但当时的界面没把这件事表达出来，而且缺了一个入口：

- 字段叫「管理台语言」，值是 Français，却摆在一屏中文界面上——谁看都像坏了；
- **个人选择一旦做出就撤不掉**：`resetLocale()` 只在「没选过的人保存站点设置时」被调过一次，
  用户自己够不着它。所以那两块一旦分叉，界面上没有任何地方能把它们合回去。

改了三处（2026-09-22 当天）：

1. 字段改叫「**管理台默认语言**」，只读态的值后面缀一句「站点默认」；
2. 顶栏下拉多一项「**跟随站点默认（Français）**」，走 `resetLocale()`——
   ⚠ 不是 `setLocale()`：后者会把这一次也记成「他自己的选择」，
   那样下次站长改了站点默认这个人还是跟不上，等于按了「跟随」却没跟上。
   这一项**只在自己选过语言时出现**：没选过的人本来就在跟着它走。
3. 那句提示改成说清两件事的区别，并指向上面那一项。

## 为什么顶栏那个下拉摆在顶栏

要用它的人恰恰是**看不懂当前这一屏**的那个人。他没法先读懂「设置」两个字再点进去找。
所以它在顶栏，而且 label 用各语言自己的写法（中文 / English / Français），不写「英语」「法语」。

## 回退：缺键显示中文，不显示键名

文案表按 `中文垫底 + 该语言覆盖` 取（和前台 `useShopCopy.ts` 同一个路子）。
`en.js` 里漏了一个键，英文界面上那一处显示中文原文，不是 `nav.goods` 这种键名——
漏翻是小事，一个看不懂的键名是把人堵死。

## 涉及的文件

### 后端（station-console）

- `u_s_siteinfo.consolelang`：新列。迁移脚本 `sql/station/migration/2026-09-22-console-lang.sql`，
  基线 `sql/station/01_station_schema.sql` 同一个提交里补上了。
- `SiteInfo`：`consoleLang` 字段 + `CONSOLE_LANGS` 白名单 + `consoleLangOrDefault()`。
  越界值一律当 `zh`，不抛异常——这一列只决定界面画成什么样。
- `SiteInfoMapper.xml`：`consolelang` 走 **coalesce**。理由和 `domain` 那条一样：
  老版管理台（dist 单独发版，后端先发前端后发是常事）不送这个字段，直赋值会把它抹成 NULL。
- `/api/me` 下发 `consoleLang`，读的是站点档案（进程内缓存）而不是会话快照——
  站长刚改完，自己这个会话里的快照还是旧的，而这恰恰是最容易被当成「保存没生效」的字段。

### 前端（station-console-ui）

- `src/i18n/index.js`：文案表 + `t()` / `tryT()` / `setLocale()` / `initLocale()` / `resetLocale()`。
- `src/i18n/locales/{zh,en,fr}.js`：三份文案表。**zh 是底稿**，en/fr 只是覆盖。
- `App.vue` 的 `<el-config-provider :locale>`：Element Plus 自带的日历、分页、确认框按钮
  跟着一起变。不做这一步的后果不是「有几个字没翻」，而是界面是法语、日历是中文。
- `main.js`：`initLocale(identity.consoleLang)` 在 `app.mount` **之前**——第一帧就要是对的语言。

### 共用组件（station-shared）

`station-shared/` 下的组件不能 import 任何宿主的 `@/`（README 里「谁都不 import 谁」那条）。
所以走注入：

- `station-shared/useStationT.js`：`const st = useStationT()`，调用写成 `st('key', '中文原文')`。
- 宿主在 `main.js` 里 `app.provide('stationT', tryT)`。
- **中文原文写在调用处**：宿主没提供翻译器、或者文案表里漏了这个键时，落回一句人话而不是键名。
  共用组件不知道自己被谁用着，兜底必须自带。

## 有意没翻的东西

1. **库里存的中文值**。`u_s_sitegoods.publishstatus` 存的就是 `'已上架'`，
   `u_s_inquiry.status` 存的就是 `'待处理'`，订单状态、跟进方式、站点状态同理。
   这些地方一律**只翻 label、不动 value**：
   - `<el-option :label="statusLabel(s)" :value="s" />`
   - 判色的 `statusType()` 仍然按中文值查表——两边都改的话，英文界面下所有状态标签都是灰的。
   把库里的值改成英文码是另一件事（要动 ERP、SQL 脚本、前台判断），不在这一轮里。

2. ~~**后端返回的提示语**~~ 和 ~~**SEO 体检的问题描述**~~ —— **2026-09-24 补上了**，见下一节。

### 后端的中文提示：前端按句式翻（2026-09-24）

原来的判断是「运行期产生的句子，不是封闭集合」。不对：**变量不封闭，句式是封闭的**。
「商品 EB-BOOT-01 不存在」每次不同，但句式只有一个，把变量部分写成 `{0}` 就能对上。

- 文案表里 `server.*` 一组 173 条，中文那一份就是后端原话（逐字，全角半角都算），
  变量写成 `{0}` `{1}`。来源：station-console 里 `new ServiceException("…")`、响应里直接放的
  文字（上传超限、汇率拉取失败原因、SEO 体检的 message / targetName / notChecked）。
- `src/i18n/server.js` 的 `translateServerText()` 做匹配。接在：`request.js`（所有 `msg`，成功和失败都算）、
  `SeoAudit.vue`、`Entry.vue`（SSO 失败的 `detail`）、`Overview.vue`（汇率错误、改币种预览的 error）。
- 抠出来的变量原样填回去，只动三样：整段是库里状态值的（「待确认」→ 译名）、中文顿号列表、「等 N 个」。
- **匹配不上就显示中文原话**——和没有这一层时一样，不会更坏。所以后端改了措辞或新加一句，
  只是那一句退回中文，不会报错；要补就在三份 locales 里加一条 `server.*`。
- 为什么不在后端做（像买家那侧的 `BuyerText`）：要改四十来个文件里的 `throw`、再发 jar；
  前端这层后端一行不动，文案和其它界面文字在同一套 locales 里。

**管理台聊天那三句**（`chat.empty` / `chat.sessionMissing` / `chat.notFound`）：a5ab6212 之后后端走
`BuyerText` 的键，管理台请求没有站点语言，`ApiExceptionHandler` 照样 render 就落到了**英文**兜底。
2026-09-24 改成「没有站点语言（= 管理台请求）就回中文原话」，由这一层翻；测试
`ApiExceptionHandlerLangTest`。三句的 `server.chat.*` 已加，中文值和 a5ab6212 之前的原话一致，
所以新旧两版后端都对得上。

4. **国家名**走浏览器的 `Intl.DisplayNames`，没有手写三份。中文那张表留着不动——
   里面有 Intl 给不出的说法（「中国香港」「ZZ = 未知 / 保留段」）。币种名同理。

## 加一种界面语言要改三处

1. `src/i18n/index.js` 的 `LOCALES`
2. 新增 `src/i18n/locales/xx.js`
3. 后端 `SiteInfo.CONSOLE_LANGS`

少了第三处的表现是「站点设置里选得上、提示已保存、进去还是中文」——和 `langs` 那个白名单
当年踩的是同一个坑。

## 自检

`node verify.js`（本轮的临时脚本，见提交说明）做三件事：用 `@vue/compiler-sfc` 编译每个
`.vue`（和 `vite build` 同一个编译器）、比对三份文案表的键集合、数还剩多少中文片段。
最后一项永远不会归零：上面「有意没翻」的那些就是剩下的。
